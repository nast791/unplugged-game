# UnPlugged — контекст проекта

Кэш для быстрого входа. Правь здесь же, если поменял архитектуру, инвариант или команду.
Правила — код `shared/`; интерфейс — `docs/terrain.md`. Файл уходит в каждый запрос, держим его сухим.

## 1. Что это

Браузерная настольная игра в духе Unmatched: hotseat за одним экраном, логика целиком в движке,
клиент только рисует и шлёт клики. Стиль доски примитивный: кружки, линии, сектора, текстуры.
Стек: Nuxt 4 (Vue 3 SFC), Tailwind 4, konva/vue-konva, vitest 4, pnpm; Node 24, Windows (PowerShell 5.1).

## 3. Движок

- **Хуки → фазы → действия.** `state.hook`: `gameStart`(1) → `turnStart`(2) → `turn`(3) → `turnEnd`(4) →
  `gameEnd`(5). Фазы хука `turn`: `handLimit` → `choose` → `movement` → `attack` → `defense` → `waiting`.
  Активна ровно одна фаза на игрока; она разрешает свои клики и объявляет `controls`.
- **`turn.index` и `round` — разные счётчики** (`shared/lifecycle/turnStart.js`): `turn.index` растёт
  каждый ход, а `round` — раз в круг, когда ход возвращается к тому, кто в этом круге уже ходил
  (`turn.actedRound`, мёртвые из списка выпадают). Проверять «все живые уже ходили» нельзя: после сброса
  списка условие срабатывает на каждом следующем ходу, и на двоих `round` рос каждый ход — регрессия
  закрыта тестом `tests/unit/core/turnStart.test.js` («на двоих round растёт раз в круг»).
- **Моменты** (`constants/moments.js`): `gameStart`(0), `turnStart`(1), `effect`(2), `picked`(3),
  `immediately`(4), `duringCombat`(5), `afterCombat`(6), `turnEnd`(7). Неизвестный — ошибка движка.
- **DSL:** `rules: [{ moment, when: [факты], any: [[факты]], then: [{ action, … }] }]` у карт и способностей.
  Факты — чистые функции от state, действие — универсальный экшен.
- **Правила одного момента независимы:** условия всех правил читаются до первого действия, потом
  выполняются их `then` по накопительному состоянию (`shared/rules/run.js`). Правило не может «включить»
  условие соседнего — иначе взаимоисключающие ветки одной карты срабатывали бы все подряд.
- **Экшены:** `SET_ACTIONS`, `SET_CARDS`, `SET_HEALTH`, `SET_FIGHTER_CELL`, `SWAP_FIGHTERS`,
  `SET_MOVEMENT`, `SET_COMBAT`, `SET_TARGETING`, `SET_CELL_TERRAIN`, `REVIVE_FIGHTER`, `PICK`,
  `FINISH_ACTION`, `RESIGN`. Клиент шлёт только `PICK`/`UI_*`.
- **Флаг «двигался в этом ходу»:** `fighter.movedThisTurn` ставит `SET_FIGHTER_CELL` при шаге по полю
  (не при расстановке), снимает начало хода; читается фактом `FIGHTERS { movedThisTurn }`.
  **Телепорт — не движение** (правило владельца): постановка бойца без прохода (обмен местами, возврат
  убитого, карта-телепорт) флаг не ставит — `SET_FIGHTER_CELL { teleport: true }`, `SWAP_FIGHTERS`
  передаёт признак сам.
- **Флаг «наносил урон в этом ходу»:** `fighter.dealtDamageThisTurn` ставит `SET_HEALTH` (`delta < 0`)
  **владельцу урона**, а не цели: `playerId` действия берётся из правила (владелец карты или умения)
  или из боя (`combat.attackerPlayerId` — урон в чужом ходу не записывается защитнику-герою); свой
  боец под своим же уроном флаг не ставит, лечение — тоже. Снимает начало хода, читается фактом
  `FIGHTERS { dealtDamageThisTurn }`; по нему читается условие «герой не наносил урон» (умение Анубиса,
  `shared/helpers/damage.js`). **Ловушка:** флаг ставится тому, *кто бьёт*, — первая версия ставила его
  цели, и суд молчал у пострадавшего вместо ударившего.
- **Значения фактов в параметрах:** `FIGHTERS` отдаёт список объектов, `COMBAT { select }` — список id,
  а `areaOf`/`adjacentTo`/`fighterIds` ждут одного бойца. `findFighter` разбирает и строку, и элемент
  списка, и объект `{ fighterId }`; `SET_CARDS { cardIds }` так же принимает и ключи, и объекты карт
  из `CARDS`/`HAND` (`cardId` объекта). `COMBAT { select }` во время битвы читает **открытый бой**
  (`state.combat`), а `winner` — итог (`lastCombat`): без этого свойства «во время битвы» не видели бойцов.
- **Радиус от бойца — в самом `FIGHTERS`:** `FIGHTERS { withinOf: '<боец>', within: N }` отдаёт всех, кто
  стоит в `N` шагах по линиям поля от него (`bfsDistance`), своя клетка в радиус не входит. Так «Сжечь
  всех дотла» Ифрита бьёт всех вокруг, включая своих, а сам герой под свой удар не попадает
  (`shared/facts/fighters.js`, стережёт `tests/unit/cards/ifrit_14.test.js`). Сторона у такой выборки
  смешанная, поэтому бот считает урон по владельцу каждого бойца (`bot/play/cards.js: listHealthWorth`),
  а не по тегу переменной: иначе своя часть урона пряталась бы за чужой.
- **Привязка карт:** карту убитого помощника нельзя объявить (атака, эффект, защита) —
  `hasFighterForCard` гейтит только объявление. Сброс и усиление (`bonus`) работают всегда: такие
  карты остаются в колоде как топливо, а не выпадают из игры.
- **Карты и бой — что умеет движок:** `HAND { of, min, max, over }` — число карт в руке, в том числе
  чужой («у противника нет карт» — `max: 0`; `over` — «у него больше, чем у меня»); `COMBAT { bonus: 'opponent' }` —
  усиление карты боя стороны («значение моей карты равно усилению его атаки» — «Саван»), с границами
  `min`/`max`/`over`/`under` сравнивают своё усиление с чужим; `SET_COMBAT { op: 'replaceDefense' }` —
  замена защиты (старая карта в сброс, второе обязательное окно защиты, автопас без карт, очередь боя
  не повторяет сыгранные шаги); `SET_REVEAL { op: 'bottom', of: 'self' }` — раскрытая карта под низ
  колоды; `ITEMS` / `SET_ITEM` — предмет-состояние для постоянных эффектов (пелена Анубиса).
  **Подпись состояния предмета одна на всех — «активна» / «не активна»** (решение владельца, m00001):
  словарь `app/constants/items.js` (`ITEM_STATE_LABELS`), `itemStateLabel` читает его раньше `item.states`,
  поэтому пак этих двух состояний не переименовывает; своё имя остаётся только у счётчика (осколки
  Снежной королевы «во льду» / «собраны»). Стерегут `tests/unit/client/item-state-label.test.js`
  и `tests/unit/client/hero-info.test.js`.
- **Суд Осириса — весы на картах** (решение владельца, m00002): пелена (`shroud`) активна с начала партии,
  и пока она активна, на картах Анубиса и Амат с тегом `scales` («пометка весов») работают пары правил
  **Помилование** (усиление карты противника не больше своего) и **Наказание** (строго больше); пелена
  не активна — карты действуют только базовым текстом. Своё усиление передаётся переменной
  (`{ fact: 'COMBAT', params: { bonus: 'self' }, var: 'mine' }`), границы — числа после `resolveVars`;
  при пасе карты в бою нет и `ok: false`, поэтому весы на пас не срабатывают. «Пелена активна» — обычное
  `ITEMS { group: 'shroud', state: 'active' }`, а выключает её умение (`turnStart` + `LOST { group: 'amat' }`);
  «у противника карт больше» — `HAND { of: 'opponent', over: true }` (роль через `playerByRole`).
  Стерегут `tests/unit/skills/anubis.test.js`, `tests/unit/cards/anubis_cards.test.js`; значок весов на
  карточке — тег в `card.tags`, а стоит он **на плашке значения**: под числом, плашка растягивается по
  высоте, а иконка типа и число остаются на своих местах (решение владельца, m00764), и рисуется он
  **обычной белой иконкой без белого кружка и подложки** (m00874; `Card.vue`,
  `TOOLTIPS.card.scales`, `tests/unit/client/card-scales-icon.test.js`). Блок иконки типа и числа
  фиксирован (54 px, по центру), поэтому **у карты без числа плашка той же высоты, что у атаки/защиты
  без весов, а иконка типа стоит посередине** (m00902).
- **Постановка в область без движения** (`SET_MOVEMENT { areaOnly, once }`, «Зал суда»): `areaOnly` заменяет
  радиус на все свободные клетки **текущей области** бойца (`sharesArea` от его клетки), а шаг ставит
  `teleport: true` — `movedThisTurn` не появляется, «не считается движением»; `once` закрывает окно
  после первого переноса (ставится **один** боец, а не оба). Обычный черновик этих полей не несёт
  (они добавляются только при `true`), поэтому форма окна перемещения прежняя.
- **Перемещение от эффекта задаёт своё поведение прохода** (`SET_MOVEMENT { … }`): `throughEnemies` —
  сквозь бойцов противника, `damageOnPass` — урон каждому пройденному (один раз за окно),
  `healOnPass` — идущий забирает столько же себе («Пепельный ветер» Ифрита: «крадёт здоровье»;
  выше `startHp` не поднимается). Маршрут считается только там, где урон или кража есть.
  **Бот это читает** (`bot/play/cards.js: actionWorth`): шаг стоит 1,5 плюс 0,25 за каждую клетку
  сверх первой, 0,5 за `throughEnemies` и по 1 за пункт `damageOnPass`/`healOnPass` — урон на проходе
  не гарантирован, поэтому он вдвое дешевле обычного урона по чужому бойцу.
- **`CELLS { terrain }` принимает строку или список** (`['lava', 'desert']`): иначе одну карту на две
  стихии не выразить. Так работал «Пепельный покров» Ифрита (сначала заменён «Вспышкой гнева»,
  теперь «Искрами»); возможность осталась в движке.
- **Временная стихия клетки — добавка, а не замена** (m00001): `node.extraTerrain` (строка или список) —
  публичное поле карты, базовая `node.terrain` не меняется; `nodeAllTerrains`/`cellTerrains`
  (`shared/helpers/placement.js`) отдают сначала базовые стихии, потом добавку без дублей.
  Ставит `SET_CELL_TERRAIN { op: 'add', cellId, terrain }` (`shared/actions/terrain.js`): не больше трёх
  стихий на клетку, уже стоящая стихия второй раз не добавляется; `op: 'clear'` снимает добавку (одну
  клетку или все). Шаг с `SET_MOVEMENT { terrainOnStep }` ставит стихию на клетку назначения — так
  «Три обещания» Ифрита поджигают пол под ним. Живёт добавка **до конца хода**: `turnEnd.exit` зовёт
  `clearTemporaryTerrains`. Клиент получает её в проекции `map.nodes` и рисует отдельным куском
  (`app/composables/ui/useBoardMap.js`, `extra*Of`), а не подменяет стихию клетки.
- **Пустое перемещение не открывается** (решение владельца): если ни один боец из списка не может шагнуть
  ни на одну клетку, `SET_MOVEMENT open` не открывает окно — свойство карты просто не срабатывает, и шаг
  эффекта помечается `skipped` («не сработало»), а не сработавшим: **шаг, который ничего не изменил,
  не выдаёт себя за сработавший** (`shared/cards/run.js: stepStatus` — сравнение `forkState` до и после
  правила; m01941, «Стена огня» Ифрита в защиту при занятых соседях цели). Так закрыт

- **Своего бойца в окне эффекта рамкой не метят** (правило владельца, m01486): окно перемещения от эффекта
  отдаёт в `highlightedFighterIds` только **чужих** бойцов из списка правила (`shared/phases/movement.js`;
  «Куда подальше» Дороти так двигает атакующего — чужого видно и понятно, кого вести), а свои Дороти и Тото
  остаются без кольца: игрок кликает по фишке (`fighterClickIntent` → `select` по `myFighters`), и только
  тогда загораются клетки, куда он может встать. Иначе кольца на клетках пары читались как подсветка
  доступных клеток; подсказка окна говорит «Нажмите на бойца…». Стерегут `tests/unit/cards/dorothy_11.test.js`
  (пара не подсвечена, клик по фишке выбирает, клетки появляются) и `dorothy_04.test.js` (чужой подсвечен).
- **Карта играется только со срабатывающим свойством** (требование владельца, §35): польза эффекта
  считается условиями движка (`bot/play/cards.js: effectWorth` — `fires` это число выполнившихся правил,
  `value` — польза по общей шкале), и карта с `known: true` и `fires === 0` получает **вес 0** — вето, как
  у «шага в никуда» (`bot/play/decide.js`). Вес сработавшей пользы — ген `effect` (1,5), отключается
  `BOT_EFFECT_WORTH=0`. Незнакомая карта без правил остаётся с прежним весом: новая механика не должна
  молча выпадать из игры. **Числа:** эффектов «впустую» 24% → 1% (720 партий), симметрия `greedy` против
  `greedy` — 50/50; замер — `bot/tools/waste.js`.
- **Эффект предлагается, только если розыгрыш что-то изменит** (правило владельца): `effectBrings`
  (`shared/cards/run.js`) прогоняет правила карты на форке и сравнивает состояние — карта с пустым
  результатом в `playableCardIds` не попадает и уходит в `disabledCardIds`: она стоит действия и не
  делает ничего, поэтому остаётся **топливом** (её сбрасывают ради усиления). Достаточно любой части
  свойства, и **негатив тоже считается**: добор из пустой колоды отнимает здоровье, поэтому «Зелёные
  очки» играются и на пустой колоде. Считает движок (`runUi`), а не клиент, поэтому «предлагается» и
  «срабатывает» не расходятся. Так закрыты: «Плач по Амат» (Амат жива), «Ожог» (нет бойца в шаге),
  «Вечность» (нет поверженной вороны), «Кристальный резонанс» (меньше пяти осколков), «Суд
  молчит» (Анубис уже двигался). Стерегут `tests/unit/cards/effect-offer.test.js`,
  `tests/unit/cards/anubis_cards.test.js` и тесты карт, которые раньше разыгрывались впустую
  (`dorothy_common`).
- **Окно клеток, которое переносит своего бойца, бот оценивает как позицию, а не жребием** (`bot/play/decide.js:

- **Темп по запасу колод — живая политика `trade`** (§36): у политики есть своё топливо (`fuel`) и запас

  считается `clock`: позади — давить (атака ×(1+1.2·дефицит), сближение выше), впереди — тянуть (добор
  дешевле, кайт разрешён). **Числа:** против `greedy` 50/50, против `aggressive` 51/48, медиана партии
  105 против 124, застреваний 3 против 60 на 2400. В браузере (`bot/play/ai.js: think`) перечисление идёт
  этой политикой; `greedy` остаётся чистым эталоном замеров. Замер — `bot/tools/stall.js`.
- **Живой ученик `qvalue` — `mlp-anubis`** (§58): переучен после судебной переделки Анубиса — 900 партий
  самоигры на новом контенте (`top-1` 93,5%, знак Q 67,2%), A/B против `mlp-e2` 51% против 49%, против
  `greedy` 55% против 45% (у `mlp-e2` было 54%). Прежний живой `mlp-e2` (§41: 2 000 партий дневника,

  константа** (`bot/play/artifact.js`): у каждой стороны
  партии может быть своя модель (`--artifact`/`--artifact-b` в `matrix.js`/`stats.js`/`export.js`,
  `SEARCH_ARTIFACT` в переменных среды) — без этого «версия против версии» невыразима. **Файл

- **Честный оракул (парная оценка в одних мирах) — проверен, не берём (§46).** `bot/learn/export.js
  --oracle-paired --oracle-eval=position` убирает шум «каждый вариант в своём мире»: самоконтроль оракула
  (тот же вопрос дважды) растёт с **50,0% до 64,7%** по лучшему варианту и с 63,0% до 78,8% по парам.
  Но стоит **8,7×** дороже, а **сила игры не растёт**: на 240 партиях 52% против 53% (обычные), на 760 —
  **обе по 53%**, лицом к лицу 50/50; живой `mlp-e2` (2 000 партий) — 54%. **Урок: шум меток — не узкое
  место.** Ни лучший учитель, ни честные метки, ни объём не пробивают 53–54% — значит упирается в класс
  модели и признаки, а не в качество цели. Прогресс экспорта пишется в `stderr` (шаг 25 партий): дорогой
  прогон иначе не отличить от зависшего, и четыре таких прогона уже потеряли по 50 минут.
- **Поиск как решение, модель как приор — механизм сделан, прироста нет; силу даёт бюджет времени (§47).**
  Прежний приор корня (`prior · log p` при `prior = 0,02`) **в решении не участвовал**: при бюджете 30 мс
  поиск успевает ~35 доигрываний на решение (5–7 визитов на вариант корня, `.workbuddy/prior-probe.mjs`),
  и добавка тонет в разбросе средних — свип коэффициента 0…30 не менял ничего (22–26 побед из 48).
  **Сделано** (`bot/play/search.js`): `rootAdvantages` — мнение модели в единицах оценки (те же числа, что
  у ученика: `Q(s, a) + 0,8 · log1p(вес)`, отсчитанные от лучшего варианта), входит в решение корня с
  весом, убывающим по визитам (`SEARCH_PRIOR_MIX · advantage / (visits + SEARCH_PRIOR_TAU)`), и задаёт
  порядок развёртывания нераскрытых вариантов; `SEARCH_TOP` — верхушка модели. `SEARCH_PRIOR_MIX=0` —
  прежнее поведение (эталон замеров). **Числа:** контроль 50/50 (1196/1204), `mix = 0,8` — 48/52
  (1151/1249 на 2 400 партиях), объединённо по сериям 51,9% против 48,1%; модель как **лист** поиска
  (`qleaf`) — ровно 50/50 (716/724); верхушка `SEARCH_TOP=3` — 47/48. **Главное:** при равном бюджете
  сильнее не приор, а доигрывания — `qprior` 30 мс против живого `qvalue` **57% против 43%** (825/615),
  `search` 200 мс — **67% против 33%** (967/473), против `greedy` — **70% против 30%** (1015/425) при
  54% у `qvalue`; живые настройки браузера (`turn`, 200 мс) дают против того же ученика **65%** (932/508).
  То есть живой режим уже сильнее модели, и вопрос не «включать ли поиск», а что даёт при том же бюджете
  больше приора. Модель в игру не промоутится.
- **Бюджет поиска: распределение и кэши — доведено, прироста нет (§48).** Раз силу дают доигрывания,
  проверено, чем бюджет покупается. **Цена доигрывания** (`.workbuddy/search-costs.mjs`): базовый конфиг
  (дерево 3, глубина 10) — 1,11 мс; плоское дерево (treeDepth 1) — **0,79 (−29%)**; роллаут глубиной 6 —
  0,72; глубиной 16 — 1,38; роллаут `greedy` — 1,10; лист на границе хода — 1,09. **Винрейт этого не
  замечает:** `search tree 1` против `turn` — 51/49, `tree 3` — 53/47 (по 288 и 900 партий, 200 мс),
  роллаут `greedy` + глубина 16 — 53, `SEARCH_EXPLORATION=0.7` — 50: всё в пределах шума, «быстрее ≠
  сильнее». **Кэши:** кэш перечисления по объекту состояния **сделан, замерен и убран** (22,3–26,1 мс
  против 20,1–23,7 — вредит); кэш остатка колоды (`unseenOf`) — в шуме, оставлен с выключателем
  `BOT_CACHE_UNSEEN=0`; карты расстояний и индекс «id → клетка» — единственный выигрыш, ≈1,2×, но он
  меньше системного шума (`BOT_CACHE_DIST=0` — выключатель). **Web Worker не делали сознательно:**
  распределение оказалось в шуме, а параллелизм в браузере стоит копирования состояния и общих кэшей.
- **Две головы модели (карты / клетки) — механизм сделан, замер в шуме (§49).** `trainer/train.py
  --two-heads` даёт два ствола и две головы: шаги (клетки) считает своя пара, всё остальное — общая;
  параметров столько же, сколько у одной головы, второй ствол стартует копией первого. Артефакт уносит
  `twoHeads` и веса `*Cell`, а рантайм (`bot/play/qvalue.js: mlpScore`) выбирает голову по признаку 3
  вектора действия — там же, где делит тренер (тест `tests/unit/bot/two-heads.test.js`). **Числа:**
  на удержанных партиях метрики неразличимы (`top-1` 64,8% против 65,0%, знак Q 78,2% против 78,6%),
  лестница против `greedy` на 900 партиях — **55% против 53%** у контроля, то есть +2 п.п. в шуме (±3,3),
  а артефакт вдвое тяжелее. В игру не идёт, живым остаётся `mlp-e2`. Вывод тот же, что у приора §47:
  дело не в том, куда положить подсказку, а в классе модели.
- **Нелинейность «состояние × действие» — механизм сделан, замер в шуме (§50).** У сети взаимодействие
  признаков живёт только внутри первого слоя, то есть **общее для всех позиций**; `trainer/train.py
  --gated` делает его своим: вектор варианта умножается на ворота из сводки позиции
  (`a' = a · σ(G · summary + g0)`, 207 параметров; при нулевых весах σ(0) = 0,5 — общая половинная шкала,
  то есть старт эквивалентен прежнему поведению). Артефакт уносит `gated`, `summaryIndex`, `Wgate`,
  `bgate`, рантайм (`bot/play/qvalue.js: mlpScore`) считает ту же формулу; тест —
  `tests/unit/bot/two-heads.test.js`. **Числа:** `top-1` 65,1% и знак Q 78,4% на удержанных (у живой
  65,0%/78,6%); против `greedy` — 54%, как у живой; **прямой матч против `mlp-e2` — 51% против 49%**
  на 900 партиях и **51% против 49% на 2 400** (1 215/1 185, шум ±2,0 п.п. — порог круга «≥1000 партий»
  взят объёмом, но паритет); `rank.js` — лучший вариант 45,2% против 45,1%, согласие 47,4% против 47,3%.
  В игру не идёт. **Итог трёх кругов по классу модели (§47 приор, §49 головы, §50 нелинейность):** три
  механизма, все доведены и замерены, все дали паритет — упирается в цель и объём, а не в способ
  применения модели; поиск с бюджетом времени тот же сигнал использует и даёт 70% против `greedy`.
- **«Рефлексия» (учиться на своих ошибках) — проверена, не берём (§45).** Два механизма: вес решения по
  величине ошибки в тренере (`trainer/train.py --reflect`: `вес = 1 + потеря/0,2 + 0,6·неуверенность`) и
  журнал паттернов ошибок (`bot/tools/errors.js`). **Числа:** артефакт с рефлексией проиграл живому
  **49% против 51%**, контроль без рефлексии — 50/50 и 54% против `greedy`. Причина: взвешивание усиливает
  решения с шумной меткой учителя (ценности оракула на клетках согласованы сами с собой на 56–60%), и
  модель подгоняет шум. **Полезное из §45:** контекст ошибок глазами модели показал, что игра теряется на
  «модель уверена и ошиблась» (потеря 0.106), а не на слепых решениях (0.054–0.071) — лечить надо
  уверенные ошибки, а не слепоту. Урок: прежде чем учить модель на своих ошибках, проверь, надёжна ли метка
  на этих решениях.
- **Что двигает игру, а что нет (§43).** Правила политики лишь **примешиваются** к оценке модели
  (`bot/play/qvalue.js: PRIOR_MIX`), поэтому **уточнение правил игру почти не двигает**: шесть новых генов
  §43 (`initiative`, `lastAction`, `actionSecond`, `deal`, `focus`, `tempo`) дали 54–55% и с собой, и без
  себя. Двигает **доля веса политики**: 0 — 51%, 0,3 — 53–54%, 0,6–3,0 — 55–56%, 6,0+ — 54%; живое
  значение **0,8**. Урок: прежде чем добавлять правило, спроси, доходит ли оно до решения — вес варианта
  может тонуть в оценке модели. Гены включаются/выключаются `BOT_GENE_<ИМЯ>=число` (`bot/play/policy.js:
  gene`), поэтому вклад каждого меряется без правок кода.
- **Оценка размена — утверждённый шаг, откату не подлежит** (§37–§38): в вес атаки добавлены шесть генов
  (`bot/play/policy.js: attackWeight`, у эталонов нулевые): `tradeCost` — усиление карты сгорает вместе с
  ней, цена `(value + bonus) / value`; `tradeRisk` — ожидание чужой атаки (`counting.js: expectedAttack`,
  без подглядывания в руку) против здоровья своего бойца, который может ударить (добивание риском не
  наказывается); `tradeWound` — материал сторон (`material: { mine, theirs }`, помощник весит половину):
  отставание поднимает цену атаки, перевес опускает; `tradeFuel` — при остатке колоды ≤3 добор дороже
  атаки; `tradeFuelSlope` — то же плавно, добавкой `slope / fuel`; `tradeCards` (§38) — `rivalHand` (чужие
  карты в руке, размер открыт) поднимает цену атаки, когда соперник не ответит картой, и опускает, когда
  рука полная; `tradeRivalFuel` (§39) — колода соперника в цене боя (`1 + gene · 0,4 · clamp((fuel − rivalFuel) / 8)`;
  знак проверен тестом — первая версия считала наоборот). **Числа:** `trade` против
  `greedy` 51/49, против `aggressive` 51/49, медиана 106, застреваний 1 из 2400. **Ценность карт:** карта без
  правил ценна как карта со свойствами (вес базовый, вето не ставится — `known: false`), а карта со
  свойствами ценна их срабатыванием (`known && fires === 0` → вес 0). Тесты —
  `tests/unit/bot/trade.test.js`, `tests/unit/bot/effect-valuation.test.js`.
  **`lastCombat.effects`** — разрешённая очередь свойств боя: что сработало, что отменили и от чего
  отказались. Заполняется при закрытии боя (потом `combat` снимается), поэтому статусы шагов после боя
  читают оттуда, а не по ссылке на `combat.effects`.
- **Вскрытие карт — публичный факт, и запись боя несёт сами карты** (`lastCombat.attackCard`/`defenseCard`
  — копии, а не ссылки на сброс): одного ключа окну битвы мало, снимок боя снят до действия и карты
  в нём лежали в руке, поэтому окно искало их в сбросах и показывало два пустых слота. Ищет
  `app/composables/game/useBattleView.js` (`cardsOfFinish`), стерегут `tests/unit/client/battle-window.test.js`
  и `tests/unit/phases/defense.test.js`.
- **Очередь боя отвечает тому шагу, чьё окно открыто:** пауз в одном бою бывает несколько (своя карта
  и чужая), поэтому шаг ищется по `source` окна, а не «первый ждущий» (`shared/cards/run.js`) — иначе
  ответ уходит чужой карте и её `picked`-правило падает, например на изменении числа боя после расчёта.
- **«заморожен» — статус бойца** (`SET_STATUS`, факт `FIGHTERS { frozen }`, снимает `turnEnd`): движок
  закрывает ему шаг, телепорт и обмен (`SET_FIGHTER_CELL`, `movementFighterRejection`,
  `movementDestinations`). **Карты и умения, которые двигают бойца, обязаны сами проверять
  `frozen: false`** в условии окна — иначе окно откроется, а клик упадёт.
- **Дальность боя — только `attackRange`:** 1 — ближний, больше — дальник; признака `attackType`
  в игре нет (решение владельца). Дальник не бьёт «по области»: и он, и ближний достают по BFS-расстоянию
  не больше `attackRange` (`shared/helpers/combat.js`).
- **«Умение в работе» — два признака движка** (для плашки «Умение» на карточке героя). **Точечное умение:** отдельного действия «разыграть умение» нет — движок сам прогоняет правила умения в своём моменте (`turnStart`/`turnEnd`/`gameStart`/`lost`), поэтому «умение срабатывает сейчас» видно по открытому окну (`state.targeting` с `source === player.skill.id`) или по черновику перемещения от умения. **Сработало само** (окна не было): `runRules` помечает `state.lastSkill = { playerId, skillId, moment }` — опция `skill` в вызове (`shared/skills/run.js`, ветка `lost` в `shared/rules/run.js`). **Действует продолжительно:** `player.skillActive` — флаг ставит и снимает **само правило умения** действием `SET_SKILL { active }` («Вечная мерзлота» Снежной королевы: ≥5 осколков в сбросе → `active: true`, ≤4 → `active: false`); движок условие не переписывает, а клиент не выдумывает своё. Оба поля публичные (`stateFields.lastSkill`, `playerFields.skillActive`) — плашку видно на карточке всем. **Срок отметки `lastSkill` считает движок:** её снимает объявление следующего действия (`SET_ACTIONS` с `delta < 0` — та же ветка, что чистит `lastCombat`/`lastBonus`), поэтому отметка живёт ровно до первого действия хода и клиенту не нужен свой счётчик шагов. Ловушка прогона: у ответа в окне `targeting` шаг очереди боя остаётся `waiting` даже в `lastCombat.effects` (окно закрывается после `runCombatPicked`), поэтому `applied`/`declined` в ленте — только у пауз, закрытых `SET_COMBAT op:'skip'`.
- **Умение-обмен («Серебряные башмачки» Дороти):** способность конца хода без автоматики и без окна
  с вопросом. Хук `turnEnd` объявляет фазу `choose`, правило на моменте `turnEnd` открывает окно цели
  по паре (Дороти и Тото в одной области, `required: false`), `choose` подсвечивает обоих и показывает
  текст способности, клик по любому выполняет `SWAP_FIGHTERS`, а отказ — общая кнопка «Завершить умение»
  (у необязательного окна свойства она называется «Закончить эффект»).
- **Окно выбора, открытое картой боя** (`SET_TARGETING` из правила боя — `immediately`, `duringCombat`,
  `afterCombat`): подсветку и клик ведёт фаза `defense` (`cardWindowOf`, `answerTargeting`) — так «Плата
  пеплом» выбирает, какого духа сжечь, а «Счёт ударов» — кого добить из бойцов противника. От обязательного
  окна отказаться нельзя (общей кнопки у него нет), от необязательного — можно: шаг очереди помечается
  `declined`, и бой доигрывается без свойства.
- **Максимальная автоматизация (правило игры):** безальтернативное решение делает движок, а не игрок —
  единственного кандидата окна он отмечает сам (`SET_TARGETING { auto: true }` → автовыбор), окно
  открывается только там, где выбор настоящий. Лишних кликов и подтверждений в игре нет.
- **Окно-переключатель («Пламя преисподней» Ифрита, «Взгляд Медузы»
  Медузы):** `SET_TARGETING { toggle: true }` — клик только отмечает цель, повторный клик по ней снимает
  отметку, а применяет выбор общая кнопка (у окна способности — «Завершить умение»). У необязательного
  окна без отметки кнопка пропускает способность, у обязательного — недоступна, пока цель не отмечена
  (отказаться нельзя). С отметкой применяется правило `picked` (у Ифрита дух умирает
  и приносит действие, у Медузы цель получает урон). Ифрит открывает окно и тогда, когда
  кандидат остался один: `auto` здесь не годится, убийство не должно случаться без подтверждения.
  Если умение хочет «авто, пока выбор безальтернативный», окно получает **оба** флага (`auto: true`
  вместе с `toggle: true`): единственного кандидата движок применяет сразу, при нескольких —
  окно-переключатель ждёт кнопку (Медуза). Отмеченную цель доска обводит той же рамкой
  активности, что и выбранного бойца (`ui.pickedFighterIds` → `useBoardMap`), ведут окно
  `shared/actions/targeting.js` и `shared/phases/choose.js`.
- **Мультивыбор цели («выберите 2 из 3»):** `SET_TARGETING { count }` принимает любое число целей
  (у окна на одну цель поведение прежнее: отметка — скаляр, и она сама закрывает окно). У окна на
  несколько целей `op: 'pick'` **добавляет** цель к списку (`picked` — массив id, `complete` — признак
  «набор собран»; дубль, недоступный или чужой кандидат отклоняются), клик по-прежнему одно действие,
  а правила момента `picked` разыгрывает общая кнопка (`UI_OK`) — она же закрывает окно. Факт `PICKED`
  в обоих случаях отдаёт **список** id, поэтому `fighterIds: '$picked'` бьёт по всем отмеченным, а
  `cellId: '$picked'` берёт первую. Обязательное окно (`required: true`) не закрывается до полного
  набора, необязательное закрывается и частичным (правило увидит только отмеченное). `auto: true`
  работает и здесь: если кандидатов ровно столько, сколько просит окно, движок собирает набор сам.
  Клиент рисует отметки чекбоксами (`CardOptions` с `single: false`), а «Подтвердить» — общая кнопка.
  Мультивыбор в фазах: `shared/helpers/targeting.js` (`windowCount`, `windowPicked`, `windowComplete`,
  `windowReady`), `shared/phases/{choose,defense}.js`.
- **Окно выбора показывает, а не спрашивает:** сверху подсказка, кандидаты подсвечены, у шага есть общая
  кнопка завершения («Закончить эффект» в окне свойства, «Закончить действие» в фазе). Вопросов «да или
  нет» и «выбрать или не выбрать» в интерфейсе нет: обязательное окно закрывается только выбором
  подсвеченной цели и кнопки не показывает, необязательное — закрывается общей кнопкой.
- **Слово одно — «битва»** (правило владельца): в текстах для игрока (тексты карт, подсказки, тултипы, надписи) «бой»/«боя»/«бою» не пишем — только «битва»/«битвы»/«битве»; «боец», «бойцы», «бойцов» — это про фигуры, они остаются. Префикс момента тоже один — `ПОСЛЕ БИТВЫ` (`CARD_MOMENT_PREFIXES`, синонима «ПОСЛЕ БОЯ» больше нет); стерегут `tests/unit/client/card-text.test.js` и `tests/unit/cards/text-paraphrase.test.js`.
- **Тексты подсказок — в словаре** (`shared/constants/hints.js`, стережёт `tests/unit/content/hints.test.js`): ключ `<фаза>.<ключ>` совпадает один к одному с ключом в `hints` фазы (плюс группа `client` — подсказки клиента: «компьютер думает», «ход отправляется», истёкший лимит). Значение — функция одного аргумента-контекста (`{ name }`, `{ limit, count }`, `{ cells }`), поэтому статическая подсказка стоит в фазе прямой ссылкой (`text: HINTS.place.placeFighters`), а динамическая — обёрткой, которая считает контекст. **Словарь знает слова, фаза — момент**: `active` (когда показывать) остаётся в фазе рядом с читаемым состоянием, а вся формулировка, включая ветки («выберите клетку» против «выберите бойца», хвост необязательного окна, «защиту съели»), — в словаре; строк подсказок в фазах не остаётся (тест сканирует исходники). Исключение — `choose.skillWindow`: текст приходит из пака героя.
- **Случайность только через сид:** `state.settings.seed` + `state.rng` (LCG в `helpers/random.js`);
  `Math.random` в логике и генераторе запрещён.
- **`runAction` не меняет входное состояние:** кирпичи правят вложенные объекты на месте (`SET_HEALTH`
  вырезает убитого бойца из `player.fighters`), поэтому ход считается на форке
  (`shared/helpers/fork.js`) — «до» и «после» это разные объекты, и сравнивать их можно. Форк бесплатен
  (A/B в одном процессе: 2762 мс против 2771 мс на 200 партий, счёт побед тот же), а глубокий
  `structuredClone` всего состояния — 7,5×. Ветку, которую движок начнёт править, дописывают в форк:
  `tests/unit/core/immutability.test.js` перебирает легальные ходы и падает с именем изменившегося пути
  (`IMMUTABLE_SEEDS=40 IMMUTABLE_STEPS=200` — широкая проверка).
- **Правила партии** (`constants/rules.js`): 2 действия за ход, рука 5, лимит руки 7, истощение 2 урона,
  2–4 игрока, сквозь своих можно, сквозь врагов нельзя.

## 4. Стихии, старты, генератор — инварианты

- **Стихия = область.** `node.terrain` — строка или массив 2–3 стихий; клетка принадлежит всем своим
  областям (`sharesArea`). Палитра: `ice #CFE9F7`, `forest #349948`, `mountains #C2CBD8`,
  `lava #DF301C` (осознанно самый тёмный, текстура золотая `#F7C846`), `desert #F0DFA8`, `water #2E9FB8`,
  `crystal #B9A6E8`, `swamp #8FA83E`, `fungus #C77BA6`, `poppy #6E9A4E`, `dead #8C8478` — всего одиннадцать.
- **На карты идут не все стихии:** `MAP_TERRAIN_EXCLUDED` в `shared/constants/terrain.js` (сейчас `poppy`)
  убирает тип из генерации, оставляя палитру, плитку и правила на месте; генератор берёт набор
  `MAP_TERRAIN_IDS`, и земля героя из выключенных на поле не возвращается.
- **Запасной стихии нет:** `terrainColor`/`terrainPattern` на неизвестном id бросают ошибку; клетка без
  стихии — ошибка контента, `createGame` проверяет стихии всех клеток при сборке.
- **Номерная клетка** = `heroStart: true` + `position` = место игрока (`seat + 1`); расстановка идёт по
  **области** номерной клетки, а не по списку стартовых. **Номерная клетка только одноцветная**
  (`shared/helpers/mapGenerator.js: isSingleTerrainCell` — правило владельца): по её стихии считается
  область расстановки, и цветная клетка на стыке зон дала бы игроку сразу две-три области. Поэтому
  генератор не берёт на старт двух- и трёхцветные клетки, а `createGame` (проверка `mapTerrainError`)
  отвергает карту с цветной номерной клеткой.
- **Старты разведены по шагам поля** (`START_GAP_STEPS = 4`, `chooseStarts`): расстояние считается
  **BFS по связям** (`stepsBetween`), а не пикселями, потому что той же мерой считаются шаг и удар.
  Наибольшая дальность атаки — 3, значит на четырёх шагах никто не достаёт чужую номерную клетку с места
  (жалоба владельца: места 2 и 3 встали рядом и герои начали бить друг друга с первого хода).
- **Клетки одной стихии связаны между собой** (`terrainAreaCellIds` — правило владельца): вся стихия —
  один связный участок по линиям-связям, а не просто соседние клетки; на старт годится только клетка,
  у которой **связная** область своей стихии вмещает всех бойцов стороны. Расстановка идёт по
  области героя, и она обязана быть цельным участком поля, а не россыпью по всей карте: без этой проверки
  разведение стартов уводило номерные клетки в разные концы поля, а помощники вставали в разных углах.
  Генератор не вырезает малой клетку, которая разрывает крупную, и отвергает поле с разрывом.
  **Соседние клетки одной земли соединены прямой линией** (правило владельца, m00780): после выбора
  стартов генератор добавляет линии между всеми такими парами (`MAX_CELL_LINKS = 8`), а поле, где линия
  не влезает (третий кружок на отрезке или предел связей), отвергает. Связи добавляются после стартов,
  потому что они сокращают путь: разведение и буфер номера перепроверяются на итоговом графе.
- **У старта есть свои клетки** (`areaCellIds` в `mapGenerator.js`, стережёт `tests/unit/content/generator.test.js`
  и `tests/scenarios/hotseat.test.js`): клетка на стыке зон принадлежит **двум** областям, и помощники соседа
  занимают её первыми — если «своих» (не общих с чужим стартом) клеток меньше пака, игрок остаётся без хода
  прямо в расстановке (находка сида 18 на четверых: помощники Ифрита заняли область Медузы, тупик, экран без
  кнопок). Поэтому генератор берёт старт, у которого своих клеток ≥ пака, а поле с меньшим не отдаёт вовсе.
- **Сторона места** (`constants/seats.js`): 1 слева, 2 справа, 3 сверху, 4 снизу, всегда; маркер смотрит наружу.
- **Генератор** (`helpers/mapGenerator.js`): поле из блоба, земель 8–10 (каждая — своя стихия),
  крупных ровно по числу игроков (`zoneKinds: 'core'`, на них номера, размер ≥ `required = max(пак)+1`),
  малых 4–8 (8–10 минус число игроков), без номера, у краёв, размером от 1 клетки до самой крупной крупной;
  **одна земля занимает не больше `MAX_TERRAIN_CELLS = 10` клеток** (крупная зона — до 9 чистых, цветной
  стык добавляет до предела);
  стихии включают `terrainAffinity` героев, но старт к ним
  не привязан: крупные земли выбираются случайно, любимая земля без крупной добирается малой; связи
  покрывают поле, линия не идёт сквозь третью клетку; старт —
  у своей стороны, не дальше второй клетки от края (край по габариту поля); клетка 112 при шаге 170×158.
  Клеток по пресету: 2 игрока — 32–36, 3 — 34–40, 4 — 34–42 (`BOARD_PRESETS`, ручные пределы `CELLS_LIMIT`
  32–42). Малые земли вырезаются из разложенного поля, чтобы не отрезать крупной земле клетки. Сосед
  номерной клетки не может быть в чужой стартовой области: между номерами остаётся малая земля или своя крупная.
- **Карты:** фиксированных карт в контенте нет — поле собирает генератор по сиду партии
  (`mapId: 'generated'`, реестр `maps` пуст); клетка = `id, x, y, terrain, neighbors, heroStart, position`.

## 5. Клиент: доска

- Геометрия — только в `useBoardGeometry.js` (математика без Vue, лежит рядом с композаблами; алиаса `~` в нём нет — только `#shared/…`: файл читают и node-скрипты, `tests/support/pattern-preview.mjs`); поле — организм `organisms/game/Board.vue` (только разметка конвы и жесты, без вычислений и комментариев), геометрия карты — композабл `useBoardMap` (клетки с секторами и текстурами, связи, фишки, маркеры, «что под курсором»), вид поля — композабл `useBoardView` (зум и сдвиг).
- **Вход доски — один проп `interactive`** (правка владельца): карту, бойцов, подсветки, рамку и клетки расстановки доска, как и панели, читает из `useGameSession` сама — экран партии не протягивает через неё то, что она и так знает. Пропом остаётся только то, чего в общем состоянии нет: `interactive` складывается из локального `pending` сессии (`useGameSession`) и `aiThinking` компьютера (`useGameAi`), поэтому его считает экран. `useBoardMap` принимает и ref, и готовое значение (`read`), поэтому его можно звать и из компонента, и из теста на голых числах; тесты доски подменяют `useGameSession`, а не пропсы (`tests/unit/client/board-clicks.test.js`).
- Порядок слоёв клетки: база → сектора стихии → текстура → чёрные разделители → обводка → номер героя
  (только на расстановке).
- **Текстуры — растровые плитки** `public/patterns/*.webp` (`PATTERN_TILES`), так выбрал владелец: WebP 512
  (осыпь гор 256 — на 512 фактура смазывается), на клетке 88–161 px; плитка кладётся на клетку целиком и
  обрезается сектором. Плитка может быть темнее заливки палитры (лава) — тогда заливка работает только для
  подписи и легенды. Плитка есть у каждой стихии и ровно одна на стихию (запасной векторный вариант льда убран),
  а стихия без плитки рисуется ровной заливкой. Эталон вида — сами плитки
  `public/patterns/*.webp`.
- **Фактура не выдумывается**, источник — `tests/support/bake-tiles.mjs`: лёд — снежинки исходника с
  выравниванием блика, лава — кинцуги (фон в коричнево-красный, жилы золотые), лес — силуэты ветвей
  (чёрная тушь с прозрачностью) поверх заливки, пустыня — тёплый кроп акварели, горы — серая осыпь
  (крупный рендер вектора и уменьшение), вода — дуотон мраморной фактуры в цвета, подобранные ближе к
  исходнику. Параметры первых трёх сверены глазами: средний цвет и плотность трещин совпадают.
- **Новая стихия — только данные:** запись в `TERRAIN` + рецепт пекаря; логику править не нужно.
- **Цифры-id клеток скрыты** (`SHOW_CELL_IDS = false` в `useBoardGeometry.js`); для отладки — `true`.
- **Клики — на сцене**, не слушателями на конва-компонентах (иначе Vue ругается на fragment-корень):
  `stage.on('click tap', …)` + `clickTarget(event.target)` поднимается от фигуры к клетке по
  `cellName/cellId/fighterId/ownerId`. Слушатель вешается на `watch(stageRef)`, а не в `onMounted`:
  сцена живёт под `v-if="stageReady"` и появляется следующим рендером, где ссылка ещё пуста — тогда
  доска молча перестаёт кликаться целиком (тест `tests/unit/client/board-clicks.test.js`).
- **Поле двигают и масштабируют** (`useBoardView`): колесо мыши приближает **вокруг курсора**, сцена
  `draggable` — поле тянут мышью, за край экрана оно не уезжает (остаётся видно не меньше 96 px по каждой
  оси), масштаб — от половины вписанного (`ZOOM_MIN = 0.5`) до 5× вписанного, `reset()` возвращает вписанный вид. Пока вид не трогали,
  он пересчитывается при смене размера контейнера; после — только ограничивается. Доска отдаёт жесты в
  композабл, а `cellAtPoint` по-прежнему читает **живое** преобразование сцены у ноды konva.
- **Партия — hotseat в браузере:** `useState('party:host')` + копия в `sessionStorage` (перезагрузка партию не
  убивает, закрытие вкладки — да); ход считается на клиенте (`runAction`), потом POST на сервер.
- **Партии нет — страница ошибки 404** (`app/error.vue`): партии живут в памяти процесса (`server/party.js`, до 32 штук) и пропадают при перезапуске сервера, а вкладка помнит свою в `sessionStorage`. Если `bootstrap` партию не нашёл (вкладке она неизвестна или сервер ответил 404), экран партии отдаёт её в `showError` — Nuxt рисует `app/error.vue` («Партия не найдена» и кнопка «В лобби»). Баннера с ошибкой поверх доски нет: отсутствие партии — это отдельная страница, а не подсказка.
- **Режим против компьютера (`mode: 'vs_ai'`):** слоты с `control: 'ai'` ведёт клиент — он хост партии.
  Лобби помечает второй слот компьютером, `useGameAi` следит за состоянием и, пока действует `ai`-слот,
  играет за него тем же кодом, что и прогоны (`bot/play/ai.js` → `bot/play/decide.js` + `bot/play/search.js`), по одному
  действию через обычный `sendAction` — движок и сервер видят ту же последовательность, что при игре
  человека. **Бюджет — 400 мс на ход** (`AI_TIME_MS`) **плюс пауза 300 мс между действиями** (`AI_PAUSE_MS`,
  решение владельца §54; было 200 мс и без паузы — бот мелькал быстрее, чем игрок успевал понять, что
  произошло): при 200 мс поиск ещё
  не сходится — ответ при 24 мирах совпадает с ответом при 96 лишь в 71%, — а на 400 мс он берёт против
  `greedy` **76% против 24%** вместо 70%. Все механизмы «умнее распорядиться теми же 200 мс» (приор §47,
  парная оценка §52, кэш миров §53, пул миров §54) замерами отклонены, поэтому куплено именно время.
  **600 мс проверены и не взяты:** на одних сидах 400 мс — 75%, 600 — 75% (по 1 800 партий, шум ±2,0 п.п.),
  то есть **плато с 400 мс**; кривая времени: 200 — 70%, 400 — 74–76%, 600 — 75%.
  **Живой режим
  с §51 — лист по глубине** (`bot/play/ai.js: think`, `turn: false`, политика `search`): решение владельца
  по замерам — при равном времени обычный поиск не хуже «думать ход целиком» (68% против 67% против живого
  ученика, 70% против 54% против `greedy`), а лист на границе хода остался переключателем `--turn=1`.
  Ядро решений
  обязано оставаться без `node:` и без `server/create.js`/`party.js`: этот код уходит в браузерный бандл
  (стережёт `tests/unit/bot/ai.test.js`), модуль бота подгружается динамически (`app/composables/game/useGameAi.js`),
  поэтому hotseat его не тянет вовсе. `syncHotseat` в этом режиме экран не передаёт: за компьютером
  человека нет.
- **Расстановка у сторон одновременная** (`shared/helpers/placement.js`, `bot/play/decide.js`):
  компьютер ставит своих бойцов **сразу**, пока человек расставляет своих, и его плашка «Расстановка»
  уходит сама — не после чужого «ОК» (это была живая жалоба владельца). Три кирпича этого:
  **слот берётся напрямую** (`bot/play/decide.js: pendingPlacementAi` → `placementActorOf`; очередь
  `actorOf` на расстановке отдаёт первого неподтверждённого, то есть человека — поиск ходил бы чужими
  бойцами и падал на «боец не ваш»), **цикл клиента ставит в первую очередь** (`app/composables/game/useGameAi.js:
  runAiCycle`: пока `pendingAiPlacer` не пуст — `think` за этот слот), и **слот подтверждается сам**
  (`confirmDoneAiPlacements` — тело фазы `place`; человек подтверждает кнопкой, исключение — герой без
  помощников: `confirmIfNothingToPlace`). Готовому слоту движок решений не отдаёт (`phase.ui` при
  `placementReady` пусто), поэтому цикл останавливается сам. **Чужих бойцов на доске при этом не видно**
  до конца расстановки у всех (`useBoardMap`: рисуем только своего смотрящего, пока `phase == gameStart`;
  проекция позиции чужих на это время тоже прячет — `party.js: hidePos`), а **рельс героев рисуется
  сразу**: `HeroHex` берёт только живое здоровье героя из проекции и позиции не спрашивает, поэтому
  установленный факт расстановки ему не нужен. Подсказка: пока бойцы стоят не все —
  `place.placeFighters`, когда встали все, но «ОК» не нажата, — `place.confirmFighters`.
  **Экран в расстановке ведёт очередь людей** (`app/composables/game/useGameSession.js: placementActor`, `handoverTarget`):
  подтвердил «ОК» — экран уходит первому по порядку мест человеку, который расстановку ещё не подтвердил
  (в расстановке хода нет, `actingPlayerId` пуст, поэтому очередь считает клиент по открытым
  `order`/`control`/`placementReady`), и передача включена **только в офлайн-игре, где человек ведёт
  несколько мест** («Одиночный режим» — бывший «Общий стол» — и «Командная игра»): против компьютера
  человек один, и экран остаётся у него.
  Стерегут `tests/unit/client/ai-parallel-placement.test.js`, `tests/unit/phases/place-autoconfirm.test.js`,
  `tests/unit/client/placement-handover.test.js`,
  `tests/unit/client/board-map.test.js`, `tests/unit/party/create.test.js`.
- **Выставленного бойца в расстановке можно переставить** (жалоба владельца, m00367): боец выбирается
  кликом по фишке, как в перемещении, — фаза сама объявляет `ui.selectFighters: true`
  (`shared/phases/place.js`; подтвердившему расстановку — `false`), клиент исполняет только флаг

  шага считает движок от выбранного бойца (`placePhaseHighlightedCellIds`). Раньше клиент решал это по

  (`placementRejection` проверяет и своих, и чужих), в подсветке она помечена `occupied` и не светится
  (`placementAreaCells`, `useBoardMap: placementGlowLevel`), а назначение роли — за подтверждением:

  никогда (двое на одной клетке). Подсказка — `place.cellTaken`.
- **Поле идёт от шапки до низа экрана, а панели лежат поверх него** (`pages/game.vue`,
  `composables/ui/useBoardView.js`, `composables/ui/useFitPad.js`): полоса поля — во весь экран
  (`absolute inset-0`) и с белым фоном (`bg-white`), канва занимает её целиком, а карта вписывается **во
  всё поле** с одинаковым отступом по краям: `fitPad` — то же `p-12` (`FIT_PAD_UNITS`), что у панелей,
  посчитанное в пикселях из единицы сетки. Каждый паддинг поля — ровно паддинг интерфейса, поэтому карта
  крупная и стоит ровно по направляющим панелей, а её низ, если карта длинная, уходит под панели — их

  пака), имя игрока, счётчик действий, здоровье, предметы, значки типа карты и усиления, валюта, время
  партии, возрастной рейтинг, страница героя. **Тексты — в словаре `app/constants/tooltips.js`** (родня
  `shared/constants/hints.js` для подсказок партии): ключ `<компонент>.<место>` (`playerCard.health`,
  `deck.click`), значение — функция с контекстом (`{ name, hp }`, `{ bonus }`), в разметке вызов

  предмета) сюда не переводятся — словарь только подставляет их в фразу. Ключи словаря и вызовы в

  стыке, а его высота — «острие плюс рамка»; толщина рамки и высота острия объявлены переменными пресета

  `tests/unit/client/tooltip.test.js`; тексты подсказок экрана партии — `tests/unit/client/game-rails.test.js`.

Тонкое обведение цветом героя и коралловое кольцо убраны: на светлой стихии не читались. **Активным боец становится кликом, а не клиентом** (m01216): авто-выбор первого поставленного бойца (`ensureSelection`) заменён на `keepSelectionValid` — `selectedFighterId` по умолчанию пуст, а сбрасывается сам, только когда своего бойца с таким id больше нет; ставит выбор `onFighterClick` и только там, где клик что-то решает (фаза окна `movement`), а клик мимо клетки (`onCellClick(null)`) и клик по странице вне доски (`pages/game.vue: onScreenClick`) снимают выбор в любой фазе. Поэтому коралловая тень не горит сама, а подсказка перемещения говорит, что делать: без выбора — «Нажмите на своего бойца, чтобы увидеть, куда он может пройти…», с выбором — «Двигайте бойца по подсвеченным клеткам…» (`HINTS.movement.moveFighters({ fromEffect, picked })`, `clientContext.selectedFighterId` → `shared/phases/movement.js`). **Доска принимает клик и без подсветки** (`useGameSession.js: fighterClickPhase`): `Board` включается по `interactive`, и раньше он зависел только от `highlightedCellIds`/`highlightedFighterIds` — а окно эффекта своих бойцов рамкой не метит (m01486), поэтому клик по своей фишке молча не доходил до доски (ни тени, ни клеток). Теперь `boardInteractive` истинно ещё и в фазах `movement`/`place` и при `ui.pickFighters`; стерегут `tests/unit/client/fighter-selection.test.js` и `tests/unit/content/hints.test.js`, а обходы (`tests/support/hotseat-ui.js`, `hotseat-browser.mjs`) держат выбор сами и кликают бойца, только когда клеток ещё нет. Данные публичные (`projectCombat` прячет только карты и числа), так что метки видны всем смотрящим; стерегут `tests/unit/client/board-map.test.js`.


- **Низ экрана — рельсы поверх поля, а не полоса** (`organisms/game/GameScreen.vue`): места игроков (`HeroRail`) стоят `absolute bottom-14 left-20`, рука (`HandFan`) — у нижнего края, полка расстановки (`PlacementTray`) — справа (`absolute right-12 bottom-205`). **Пока открыт любой оверлей, рельсы, рука и полка скрыты** (`v-if="!compact && !anyModalOpen"`): в реестр модалок себя кладут и шторка героя (её открывает `HeroRail`), и окно выбора героя номерной клетки (`addActiveModal('pickNumHero')`). **Модалку нельзя держать внутри полосы, которую она сама прячет:** окна стопок (`HandWindow`/`DeckWindow`/`DiscardWindow`) и `HeroDetailsModal` рисует экран партии (`GameScreen.vue`), иначе окно снимало бы себя. Второй вид экрана — **компактный** (`compact`, кнопка вида в `TopRail`): без рельсов, руки и полки, только доска, подсказка и рельса действий.
- **Расстановка — полка аватарок и светящиеся клетки:** движок в фазе `place` отдаёт `placementCells: [{ id, occupied }]`, поэтому **область героя светится всю расстановку**, а не только когда боец выбран (`highlightedCellIds` — допустимые клетки именно выбранного бойца); `occupied` считается по **своим** бойцам (чужую расстановку прячет проекция, `party.js`). Доска рисует кольцо поверх границы клетки, и **состояние ведёт свечение голубым фирменным** (`PLACEMENT.free = #22d3ee`, решение владельца): свободная клетка области — голубое кольцо и мягкое гало (`× 1`), клетки активного бойца — то же кольцо с гало `× 2` **без пульсации**, клетка под курсором при перетаскивании — гало `× 3` **с пульсацией** (`pulse` в `useBoardMap`, интервал 16 мс, включается, как только движок ждёт клик по клетке); обводку кольцо не перекрашивает — в расстановке граница клетки остаётся родной, а подсветка допустимых клеток в перемещении, атаке и защите рисуется тем же голубым кольцом и гало, что и при расстановке (`isActiveCell` = `highlightedCellIds` ∪ `placementCells`); **серое без свечения** (`PLACEMENT.busy`) — клетка уже занята своим бойцом. **Полка** (`molecules/game/PlacementTray.vue`, **столбиком** у правого нижнего края экрана) — аватарки тех, кого **мне** ещё ставить: **голубое кольцо `border-info` и мигающая подсветка** (`.placement-blink` в `app/assets/styles.css`; `size-68` — владелец просил заметнее), **коралловое** (`border-accent` + свечение) у выбранной; клик выбирает бойца, захват (`draggable`) выбирает и кладёт его id в буфер перетаскивания. Клетку под курсором при перетаскивании считает доска (`cellAtPoint` в `boardGeometry.js`: обратное преобразование **живой** сцены — сдвиг и зум читаются у ноды konva, а не из props — плюс ближайший кружок; клик по той же клетке даёт тот же id через `clickTarget`), бросок уходит `select-node`, ставит бойца экран; клик мимо клетки доска отдаёт как `select-node: null`. **Бросок принимает только подсвеченную клетку** (та же, куда прошёл бы клик): ярче всего светится именно она, а промах по чужой клетке ничего не делает — выбранного бойца не сбрасывает (сбрасывает только клик мимо, §«клик по неподсвеченной клетке»). **Умолчание браузера на `dragover` отменяется всегда**, даже когда доска сейчас не слушает клики: иначе курсор превращается в «запрещено» и перетаскивание читается как поломка. **В расстановке доска живая и на ходе компьютера** (`:interactive="(boardInteractive && !aiThinking) || isPlacement"`): расстановка у каждого игрока своя, а `sendAction` строит ход на последнем состоянии и сериализует запросы, — человек не обязан ждать, пока компьютер расставит своих. Подсказка «компьютер думает» в расстановке поэтому не показывается (`boardWaitingForAi` в `pages/game.vue`). **Выбор бойца живёт в `useState('party:selectedFighter')`**, а не в локальном `ref` композабла: `useGameSession()` — не синглтон (у каждой панели свой экземпляр), и полка иначе не увидела бы выбор доски; в расстановке автовыбор молчит (`ensureSelection`), а клик по неподсвеченной клетке, мимо клетки или по любому месту экрана вне доски **снимает активность** (`clearFighterSelection`), а не ругается сообщением. «Завершить» активна, только когда все мои бойцы на поле (`place.ok.enabled`).
- **Экран партии — поле во весь экран, всё остальное над ним** (`pages/game.vue`): корень `h-full`, шапка, дальше `main` от шапки **до низа экрана**, доска — `absolute inset-0`. Над полем висят (все `pointer-events-none`, чтобы клики доходили до доски, а интерактивные дети включают их обратно): **подсказка** (`HintsWindow`, сверху по центру), **окно битвы** (`BattleWindow`, по центру, `z-30`, открыто только пока идёт `combat`) и **окно вариантов свойства** (`organisms/game/ChoicePanel.vue` — те же `CardOptions` с отметкой и общей кнопкой «Подтвердить»), справа сверху — плашка лимита времени и раскрытые карты. **Высота сайта — ровно `100dvh` на любой странице** (`app/app.vue`: `Html`/`Body` `h-dvh overflow-hidden`; `layouts/routerWrapper.vue` и `layouts/default.vue` тоже `h-dvh`), поэтому страница героя скроллится внутри себя (`h-full overflow-y-auto`), а не растит документ. Отладочные панели партии (состояние движка, переключение смотрящего, «Сдаться», список руки) из экрана убраны вместе с дублирующими компонентами — по плану они уезжают в панель по флагу «показывать отладку» (`docs/ui-plan.md` §5.1).
- **Рука — веер карт** (`organisms/game/HandFan.vue`; состояние читает `useGameSession` сам, входов нет): карты отсортированы по типу (`CARD_TYPE_ORDER`), внутри типа по значению вниз, потом по названию, и лежат **внахлёст**: веер считает раскладку от числа карт и ширины окна (`SINK = 104`, `MIN_EXPOSE = 22`, `MAX_SHARE = 0.52`, `EXPOSE_SHARE = 0.5`), выдвинутая карта уходит выше веера, а не обрезается. **ЛКМ** поднимает карту на передний план, **вторая ЛКМ по ней** разыгрывает её (`onCardClick`: атака, защита или эффект — по фазе решает движок), **ПКМ** показывает карту крупно оверлеем через `Teleport` в `body` (`data-esc-layer`, закрыть — клик или Esc), а **перетаскивание** карты (`useCardDrag`, порог `DRAG_THRESHOLD = 10`) на слот сброса (`[data-drop="discard"]`) сбрасывает её ради усиления (`canDiscardBonus`/`onBonusDiscard`). Подсказки по кликам — тултип на самой карте (`ATooltip`, `TOOLTIPS.hand.card`), якорь — карта (`data-hand-card`), поэтому на пустой зоне веера подсказки нет. **Выдвинутая карта живёт до первого дела мимо неё:** клик по любому месту экрана, кроме самой карты, опускает её (слушатель на `document` в фазе **захвата** — иначе клик по канве и по чужим панелям не долетел бы), а закрытие крупной карты возвращает её в исходное состояние.
- **Задизейбленная карта** (`Card.vue`, проп `disabled`): её нельзя разыграть сейчас, но можно смотреть и увеличивать. Карта накрыта плотной вуалью `bg-app/45` (не прозрачность, а затемнение) **поверх всего содержимого** (`z-20`: и ромбик усиления, и подписи идут под ней), а **замок `lucide:lock` — единственное, что вуаль не гасит**: он лежит в левом нижнем углу картинки (`absolute bottom-8 left-8 z-30`). **У играбельной карты, которую можно скинуть ради усиления перемещения, на том же месте стоят ноги** (решение владельца, m00001): `MoveIcon` из `app/svg/game/move.svg` — та же иконка, что в круге над колодой, проп `boost`, подсказка `TOOLTIPS.card.boost`; панель передаёт `boost = canDiscardBonus && cardBonus(card) > 0 && isCardPlayable(card)` (карта без усиления — без ног, m00408), а шаблон выбирает `v-if="disabled"` (замок) / `v-else-if="boost"` (ноги), поэтому у задизейбленной карты всегда замок, а у играбельной без усиления — ни знака, ни ног. **ЛКМ по задизейбленной карте только выдвигает её и возвращает обратно** (второй клик опускает карту в исходное состояние) — вуаль при этом остаётся: выдвижение не значит «карту стало можно разыграть», а целиком её показывает только ПКМ (увеличенная карта рисуется без вуали). Панель передаёт `disabled = !isCardPlayable(card)`.
- **Текст и варианты на карте** (`Card.vue`): `card.text` и `card.options` (список `CardOptions` с точкой, без кликов) живут **в одном скролле** `AScroll`: раньше варианты были отдельным блоком, и на карте «Три обещания» текст «Выберите одно свойство:» выдавливался в ноль.
- **Свойства-опции в тексте карты — строки, а не проза** (решение владельца, m00582): в тексте пишутся словами («Помилование: …», «Наказание: …»), поэтому `cardTextBlocks` (`useGameHelpers.js`) поднимает каждую опцию из словаря `CARD_TEXT_OPTION_LABELS` (`app/constants/cards.js`) **на свою строку нового абзаца**, а оставшийся текст предыдущего абзаца остаётся его хвостом («… и обещает суд.»). Строка свойства получает `label`, и карта рисует её **коралловым заголовком** над текстом — **без плашки и вертикальной полосы** (решение владельца, m00935), между заголовком и текстом отступ (`mb-4`, m00919; `CardText.vue`, тон `card` = 12 кегль, `page` = 16 для страницы героя, активный момент — акцент). **Эти строки не кнопки**: выбрать их нельзя, `CardOptions` остаётся только у настоящих вариантов (`card.options` / окно выбора). Стерегут `tests/unit/client/card-text.test.js` и `tests/unit/client/card-option-lines.test.js`.
- **Низ карты** (`molecules/game/Card.vue`): владелец карты **по-русски через разделитель** (`cardFighterLabel` из сессии — «Анубис», «Амат», «Любой», а не id из контента; карта в окне битвы чужая, поэтому боец ищется по всей партии — у всех игроков и среди павших `lost`, — а не только по своим; подпись всегда с большой буквы — первая буква поднимается в `Card.vue: ownerLabel`) и число копий `×N`; картинки нет — в слоте арта остаётся только фон.
- **Стопки, слоты и завершение — молекулы** (`molecules/game/`): `SlotCard.vue` — квадратный слот (`button` или `div`, `data-card-anchor`, `data-drop`) с иконкой-глифом и числом: так нарисованы кнопки панели героя и счётчики руки, колоды и сброса (`HeroRail`); `pulse`/`out` рисуют акцент, `disabled` — плотную выключенность, тултип `ATooltip` выключается без подписи (`:disabled="!label"`), поэтому **слот, который нельзя нажать, не обещает клик**. `FinishButton.vue` — общая кнопка завершения по `ui.controls.ok` или подтверждения выбора (`TOOLTIPS.rail.ok({ label })`, подпись «Подтвердить» при отметке), он же ставит `data-ok-control`, по которому `BattleWindow` закрывает итог битвы; в `TopRail` она стоит первой.
- **Три стопки героя — три окна одной формы** (`molecules/game/PileWindow.vue`): `HandWindow` («Рука: …»), `DeckWindow` («Колода: …», карты закрыты) и `DiscardWindow` («Сброс: …») открываются `openModal('hand'|'deck'|'discard', { playerId })` и имеют один заголовок (цвет `HERO_INFO_TONE`), одну линию под шапкой и один крестик. **Колода нажимается только когда её карты видны**: проекция шлёт карты колоды лишь раскрытой стопке (`adaptPartyView` → `deck`/`deckVisible`), поэтому слот колоды погашен, а умение «посмотреть верхние карты» разбудит его и покажет карты тем же окном. Карты в `DiscardWindow` сгруппированы по типам (`CARD_TYPE_ORDER`) и внутри типа — по копиям: копии лежат друг на друге со сдвигом 6 px (`-ml-224 -mt-6`), поэтому число копий видно по стопке.
- **Окно вариантов свойства — выбор с подтверждением** (`ui.choices` + `CardOptions.vue`): движок отдаёт окно `kind: 'options'` с кандидатами; в проекции (`party.js`) у него есть `kind`, `count` и `picked`. Клиент рисует варианты одним и тем же `CardOptions`: на карте в руке — `static` (точка и текст, не кликается), в окне — `interactive` с **радио** (`lucide:circle`, когда `count = 1`) или **чекбоксом** (`lucide:square`, когда движок разрешит несколько), а отмеченный вариант помечается **зелёной галкой** (`lucide:check`, `text-success`). **Клик по варианту только отмечает** (`onChoiceClick` → `PICK { kind: 'option' }` — движок ничего не применяет), **применяет общая кнопка завершения** (`onFinishAction` → `UI_OK`): в `shared/phases/defense.js` это `pickOption` / `confirmOption` (`runCombatPicked` → `close` → `advanceCombat`), в `shared/phases/choose.js` — своя пара для эффектных карт. `ok.enabled` включается отметкой; у обязательного окна без отметки кнопка выключена (подтверждение без отметки — ошибка), у необязательного — отказ (`declineOption`). Кнопка в этом состоянии подписана «Подтвердить». **Мультивыбор («выберите 2 из 3») движок умеет** (`SET_TARGETING { count }`, §3): `count` приходит в проекцию, `single` выключается — варианты рисуются **чекбоксами**, отмеченные — зелёной галкой, а статус окна показывает «Выбрано 1 из 2». Кнопка завершения включает подтверждение только когда набор собран (`choiceComplete`), а у необязательного окна движок разрешает закрыть его и частичным выбором. **Подпись варианта — текст свойства целиком, а не id** (правило владельца, m01158): движок кладёт её прямо в кандидата окна (`title` из `card.options[].text`, `shared/rules/run.js: optionsWithStates` → `shared/actions/targeting.js`), потому что окно, открытое эффектом карты вне боя (`choose`), `ui.choices` не собирает — и клиент рисовал `heal`/`draw`/`step`. `ChoicePanel.vue` склеивает `ui.choices` и кандидатов **с дедупликацией по `optionId`** (иначе боевое окно показывало каждый вариант дважды: с текстом и с id); в `CardOptions.vue` строка варианта выровнена по центру кружка (`items-center`, не `items-start`) — иначе текст стоял чуть выше радио.
- **Проекция:** `party.js` прячет чужое, `adaptPartyView.js` переименовывает `hook` в `phase` и оставляет на клиенте **свою руку картами, чужую числом** (`handCount` — размер руки открыт всем, `shared/constants/deck.js`), сброс — картами всем ролям (по нему открывается сброс любого места), колоду — только числом `deckCount` (её карты не едут даже владельцу), а павшие бойцы (`lost`) — копиями всем ролям: по ним окно битвы и панель героя показывают убитых; `useGameSession`: `myDiscardCount`; счётчик действий клиент берёт оттуда же отдельными числами (`actionsLeft`/`actionsTotal`/`actionsBonus`) — у `view` поле `turn` это номер хода, а не объект хода, и читать счётчик из него значило показывать «1/1» посреди хода.

## 6. Контент и IP

- Переиспользуем механику, не тексты: названия карт, флейвор и точные числа из оригинальных наборов не
  копируются, формулировки пересказываются.

  `tests/unit/bot/counting.test.js` («подмена скрытого числа не меняет выбор»).
- **Нечисловой предел шагов — это «по умолчанию», а не ноль.** `playDuel` берёт `maxSteps` из флагов CLI,
  и с `null` цикл `for (step = 0; step < maxSteps)` не делает ни шага (`0 < null` — ложь), поэтому партия
  сразу считалась незавершённой. Теперь `playDuel` сам приводит нечисловой предел к значению по умолчанию —
  так же, как это делает любой другой потребитель отчёта. **По умолчанию 1200 шагов, а не 400** (§42):
  партии Анубис ↔ Снежная королева у двух контролей идут 400–900 шагов, и лимит 400 объявлял их
  незавершёнными (49 из 1800 в эталонной серии), хотя они кончаются сами — истощением. Урок: «незавершённая»
  партия — это чаще «длинная», чем «тупик»; прежде чем лечить политику, проверяй её с бо́льшим лимитом.
- **Дневник обязан считать признаки теми же, что рантайм, а `chosen` — быть выбором бота.** `onStep`
  (`bot/play/duel.js`) отдаёт `payload` — действие **вместе с** `playerId`, поэтому сравнивать его со
  списком вариантов нужно без владельца (иначе индекс молча уходит в 0), а признаки действия для
  `qvalue`/`search` считаются по весам **жадного предлагателя**, а не по softmax модели (§23,
  `bot/learn/export.js: actionKey`/`PROPOSES_GREEDY`).
- **Лист на границе хода имеет смысл только в свой ход, а предел времени — и внутри роллаута.**
  `turnEnd`/`replyTurn` в чужом бою вырождаются в оценку текущей позиции (все варианты защиты равны),
  поэтому `searchAction` сам снимает их вне своего хода (`turnPlan` в ответе). Бюджет `SEARCH_TIME`
  проверяется и между доигрываниями, и на каждом шаге `rolloutEnd` (`clock`/`timedOut` в отчёте) — иначе
  один длинный роллаут пересиживает лимит; лимит итераций при заданном времени снимается сам (§25,
  `docs/student.md`).
- **Расширение вектора признаков действия ломает совместимость дневника и артефакта.** После блока
  признаков клетки (`bot/play/actionFeatures.js`, `ACTION_FEATURES` 20 → 23, §28) старые дневники

## 10. Открытые задачи

- Текстуры дожать до вкуса владельца через `bake-tiles.mjs` (кроп и дуотон леса и воды,
  кроп и тёплый сдвиг песка, размер и яркость гор, кроп и выравнивание льда); сравнение — по пробе пекаря.
- Легенда «цвет → стихия» в лобби; подсказка со стихией при клике по клетке.
- Выбор числа игроков/размера поля и перегенерация из лобби.
- Метрики бота по стихиям; ресурс героя в решении: в оценке листа признаки сделаны из пака
  (`bot/play/resources.js`, §19), а в `leafScore` и весах политики (катушки Теслы, осколки Снежной королевы)
  ещё нет. Политики разделены
  (`bot/play/policy.js`): `random` — фаззинг и покрытие, `greedy` — осмысленная игра и метрики, `search` —
  поиск по детерминизациям (`bot/play/search.js`, не веса), `cards` — жадный без признаков позиции и усталости
  (эталон §13–§14), `economy` — без признаков карты и свойства (эталон §12), `basic` — вообще без признаков
  (эталон §10); числа читают по `greedy` (`docs/hero-balance.md` §10, §12–§18), `random` — свойство
  случайного бота (§9). Фаззинг идёт всеми.
- Дальше по лестнице бота: **веса подбирали** (`bot/tools/tuner.js`) — прироста нет, значит узкое место не в
  числах. **Признаки сделаны в три этапа:** рука, добор, цена карты и выбор цели (§12, +4 п.п. над
  `basic`); ценность карты в бою и свойства героя по своей карте — варианты катушек Теслы, метки осколков
  Снежной королевы (§13, +1 п.п. над `economy`); позиция и усталость — отход из-под удара, своя стихия,
  удержание места и запрет крутить тонкую колоду (§15, +1 п.п. над `cards`, против `random` — 60%).
  Три «плюс процент» подряд — сигнал, что локальные признаки исчерпаны: дальше решает **поиск**, который
  считает последствия хода. **Поиск сделан** (§16): мир собирается из остатка колоды лениво
  (`bot/play/search.js` + `bot/play/counting.js`), дерево растёт по UCT внутри ветки, роллаут идёт агрессивной
  политикой, лист оценивается по здоровью и запасу колоды; включается `--policy=search`, партии считают
  воркеры (`--workers=N`). **Результат:** `search` против `greedy` — **64% против 36%** на 599 партиях при
  бюджете 32 доигрывания и **73% против 27%** при 96; **бесплатного паса в игре нет** (в фазе объявления
  доступны карта или клик по колоде, а маневр всегда тянет добор), поэтому колода — единственные часы, и
  перетягивание заканчивается истощением: в первом замере с моим лимитом 150 шагов «незавершённых» было
  165 из 360, при штатном лимите 400 — 1 из 600, а агрессивный роллаут сократил партии (24 партии: 12 с
  против 292 с). Партия стоит 1,6 с против 2,7 с. Бюджет масштабируется (8 — 60%, 32 — 64%),
  а **дерево внутри ветки прироста не даёт** (разница с плоским в пределах шума при обоих бюджетах) —
  значит дальше решает оценка, а не размер дерева. **Оценка проверена** (§17): обученная линейная модель
  (`bot/play/value.js`, `bot/learn/train.js`, политика `net`) **проиграла** ручной формуле — 46% против 54% на 600
  партиях: линейной модели на признаках без героя не хватает различия архетипов (в весах `fighters` и
  `resources` вышли с обратным знаком). Кэш перечисления действий не дал ничего (0,99×, убран), зато кэш
  **карт расстояний** в `bot/play/duel.js` дал ×1,34 на партию (9,0 → 6,7 с). Ход с бюджетом времени —
  `bot/tools/think.js` (`think(state, playerId, { timeMs })`): за секунду поиск успевает ~290 доигрываний, при
  250 мс на ход сила против `greedy` — 66%. **Признак героя и провод в клиент сделаны** (§18): к признакам
  добавлены `hero:<id>`, `rival:<id>` и взаимодействия с героем (46 признаков), обучение переехало в
  воркеры (`--workers=N`) — 1500 партий и 72 959 позиций за 18 минут, точность 66% → 72%, базовый
  `fighters` из минуса в плюс; **но силу игры это не подняло** — `net` против `search` 49% против 51% на

## 12. Клиент: правила компонентов и вёрстки

Конвенция владельца, соблюдаем без исключений (полностью — `.cursor/rules/code-style.mdc`):

- **Каталоги:** `app/components/atoms/` — универсальные кирпичики, имя всегда с `A` (`ALoader.vue`);
  `molecules/` — небольшие сборки из атомов (карточка героя, карточка режима); `organisms/` — секции страницы, внутри
  `organisms/lobby/` (`Menu`, `ExitScreen`), `organisms/layout/` (`Footer`, `ProfileBar`),
  `organisms/game/` (`GameScreen` — экран партии, `Board` — поле на конве, `HeroRail`, `HandFan`,
  `TopRail`, `HintsWindow`, `BattleWindow`, `ChoicePanel`, `GameMenu`),
  `organisms/modals/` (`ProfileModal`, `TableSetupModal` — модалка настройки **одиночного режима**; у каждого
  режима своя, поэтому и имя по режиму, а не общее `Setup`; режим назывался «Общий стол» —
  `shared/constants/modes.js`). **Имя компонента = имя файла** (задано `components`
  в `nuxt.config.ts`; локальное имя в экране может отличаться — доска импортируется как `<GameBoard>`, чтобы
  тег читался).
- **Организм в корне всегда `<section>`**, не `<div>`; смысловые теги внутри остаются (`<nav>` в меню).
- **В `.vue` первым идёт `<template>`, вторым `<script>`**; блок `<style>` запрещён — стили только в
  `app/assets/styles.css` и классами Tailwind.
- **Пикселей в утилитах нет** (правило владельца): размер пишется масштабируемым числом — `text-9`,
  `p-4`, `h-84`, — оно считается от `--spacing`/`--text` и сжимается вместе с экраном; фиксированное
  `text-[9px]` или `p-[2px]` выпадает из fluid-шкалы и на другом мониторе стоит не там, где задумано.
  Число утилиты — это единица сетки: 9 = 9 px на 1920 и меньше на узком экране.
- **Там, где длину не задаёт утилита, — `calc(var(--spacing) * N)`** (правило владельца): тени,
  градиенты-точки, `translate3d`, `outline`, рамки в собранных руками стилях — всё в единице сетки
  (`shadow-[0_calc(var(--spacing)*2)_calc(var(--spacing)*10)_0_rgb(0_0_0/45%)]`, `keyframes` в
  `app/assets/styles.css`). Пиксели остаются только там, где их требует сам CSS — в `@media` и
  `--breakpoint-*`, в объявлении единицы `--spacing`, — и в числах, которые измеряет JS у DOM
  (`getBoundingClientRect` → `style.width = ${size}px`).
- **Комментариев в разметке нет** (правило владельца): ни `<!-- … -->` в шаблоне, ни пояснений между
  атрибутами.
- **В пресетах `app/ui/*.js` комментариев нет** (правило владельца): это файл стилей, в нём только слоты
  и классы.
- **Комментариев в коде почти нет** (правило владельца, §9): пишем только в самом крайнем случае и
  **максимум две строки**. Их было столько, что за ними не видно кода; всё, что нужно объяснить, живёт
  в `docs/` или в AGENTS.md, а не рядом со строками. Исключение — короткая ссылка на грабли, которых
  в коде не видно: **`rounded-full` перебивает радиус из пресета** (`border-radius` — одна группа
  утилит), поэтому в карточке места он стоит в `card` — без него скругление 8 пропадало (см. §9).
- **Атомы безстилевые, на `reka-ui`, по концепции preset/ui:** классов в разметке нет — только слоты
  пресета через `cn()`; пресеты — **по файлу на компонент** (`app/ui/button.js`, `app/ui/modal.js`, …),
  собираются в `app/app.config.js`, читает их `useUI(key)` из `app/composables/ui/useUI.js`
  (`appConfig.ui[key]`), локальные правки — проп `ui`. Склейка классов — только `cn` из `app/ui/cn.js`
  (там же зарегистрированы группы наших fluid-утилит и конфликт `w`/`h` с `size`: **правка `ui` обязана
  перекрывать пресет** — иначе квадрат пресета (`size-36`) побеждал правку `h-48 w-192` порядком утилит
  в CSS и размер приходилось помечать `!`; стережёт `tests/unit/client/cn.test.js`). Состав атомов: `AScroll` (общий скролл,
  применяется и внутри других атомов), `AModal` (по имени: `openModal(name, payload)`,
  `closeAllModals()`), `AButton`, `ASelect`, `ADropdown`, `ARadio`, `ARadioGroup`, `ACheckbox`,
  `ACheckboxGroup`, `AAvatar`, `APicture`, `ATabs`, `ATooltip`, `ASwitch`, `ALoader`, `AHexagon`
  (гексагон: слой-рамка и слой-тело режутся одним `clip-path` из пресета `app/ui/hexagon.js`;
  входы только `preset` и `ui`, размер и цвет задаёт вызывающая сторона — классом на атоме
  (склеивает его Vue) и правкой слотов через `ui`, как в `ACheckboxGroup`).
- **Композаблы разложены по папкам: `ui/` — интерфейс, `game/` — игровая логика, `animations/` — анимация**
  (`ui/`: `useUI`, `useModal`, `useToast`, `useConfirm`, `useExitScreen`, `useGameMenu`, `useProfile`,
  `useLobbyBoot`, `useSeoTitle`, `useSettings`, `useCardDrag`, `useDraggable`, `useSortable`,
  `useClock`, `useBoardGeometry`/`useBoardMap`/`useBoardView`, `useReactiveOptions`; `game/`: `useGameView`,
  `useGameSession`, `useGameHelpers`, `useGameAi`, `useGameHint`, `useBattleView`; `animations/`:
  `useCardFlights`, а её словарь — `app/constants/animation.js`). **Правило: рисует и слушает — в `ui/`,
  состояние партии и правила — в `game/`, движение — в `animations/`**; композабла вне этих папок нет.
  **Состояние у них модульное
  (`ref` в модуле), а не `useState`**: модалку, тост, экран выхода и меню партии открывает клиент, в
  SSR-рендере они пусты, а `useState` раздал бы одно состояние сразу всем запросам (первая версия
  `useModal` звала `useState` через `runWithContext` — в Nuxt 4 он вернул промис, и модалка падала с
  `Cannot read properties of undefined (reading 'includes')`). **Тост** (`ui/useToast.js`) общий по той же
  причине: пишет его тот, кто обработал клик, а рисует лобби; новое сообщение заменяет прошлое и
  перезапускает отсчёт, а `clearToast` на уходе экрана гасит его, иначе висящий тост встретил бы
  возвращение. **Экран выхода** (`ui/useExitScreen.js`) — прощание с кнопкой возврата, а не закрытие
  вкладки: `window.close` работает только для окон, открытых скриптом; видимость общая, потому что
  показать её может любой пункт «Выход».
- **Перетаскивание — одно на всю игру** (`useDraggable` + `useSortable`, `app/composables/ui/`): указатель
  с порогом начала (`threshold`), `axis`, `clamp`, клавиатура, отмена по `Esc`; движение и отпускание
  указателя ловятся **на `document`**, пока идёт перетаскивание (на элементе они теряются, как только
  указатель ушёл с него, — перетаскивание тогда выглядит «не работает»). Порядок списка —
  `handleProps`/`targetProps` (метка `data-sortable-index`), `move`/`moveBy`, режимы `insert` и `swap`.
  **Колбэки — `(значение, context)`, позиция первой:** цель под курсором лежит в `context.pointer`, и
  поиск её в первом аргументе уже ломал перестановку молча. Порядок считает чистая функция `reorder` из
  `app/composables/ui/useSortable.js` (`reorder`, под тестом), перестановка указателем — `tests/unit/client/sortable-dom.test.js`
  (happy-dom, элемент обязан быть в документе). `touch-none` на блоке — забота потребителя.
- **Время — счётчик от отметки, а не от интервала** (`useClock`): `setInterval` дрейфует и замирает в
  фоновой вкладке, поэтому показываем производную `Date.now() - отметка`, а общий тик лишь пересчитывает
  показ. Один композабл на всё: `mode: 'up'` — от нуля, `mode: 'down'` — к нулю (`limit`), у каждого
  счётчика своё имя (`key`) и **своё хранилище** (`unplugged:clock:<key>` в `sessionStorage`), поэтому
  счётчиков может быть сколько угодно. **Время не пишем в `state`** — он воспроизводим по сиду, и
  `Date.now()` внутри правил сломал бы и бота, и тесты на неизменность.
- **Поле ввода — атом `AInput`** (`label`, `hint`, `error`, `numeric`, слоты `prev`/`next`), как `AScroll`
  для скролла: свой `<input>` руками не пишем. Ошибка поля связана с ним через `aria-describedby`.
- **Реестр модалок — модульный `ref`, а не `useState`:** модалки открывает клиент, а `useState` через
  `runWithContext` в Nuxt 4 возвращал промис и ронял рендер (`Cannot read properties of undefined
  (reading 'includes')`); состояние реестра живёт до перезагрузки страницы.
- **В `app.config.js` импорты только через alias** (`~/ui/button.js`): относительные пути в dev-сборке
  Nitro разрешались от корня диска (`Cannot find module 'C:\app\ui\avatar.js'`).
- **`APicture` — без форматов:** растровые файлы у нас всегда WebP, поэтому art-direction по брейкпоинтам
  (`lg:src="…"`, имена из `ui.screens`), прелоад вешается `media`-ссылками (браузер тянет только текущее
  разрешение), по умолчанию `loading="lazy"`.
- **SVG живут в `app/svg/`** (`app/svg/brand/logo.svg`) и импортируются как компоненты через
  `vite-svg-loader`; в `public/` остаются только те, что браузер забирает по URL (фавиконки и иконки
  приложения). Файлы знака собирают `tests/support/bake-brand.mjs` и `bake-wordmark.py`.
- **Компонент ради двух тегов не заводим:** иконка или логотип, обёрнутые в ссылку, — это разметка
  страницы (`<NuxtLink><BrandLogo /></NuxtLink>`), а не компонент. Компонент оправдан, когда в нём логика,
  слоты или несколько осмысленных частей.
- **Всё кликабельное — «рука»:** одно общее правило в `app/assets/styles.css` (`button`, `[role='button']`,
  `select`, `summary`, `a[href]`, `label[for]`; `:disabled` — «нельзя»), в компонентах `cursor-pointer`
  не дублируем.
- **Проектные композаблы в новых файлах импортируем явно** (`~/composables/...`): `pnpm dev`, поднятый до
  появления файла, его в автоимпортах не знает и падает в рантайме (`useProfile is not defined`), при этом
  сборка остаётся зелёной.
- **Комментариев в разметке нет** (правило владельца): в `.vue` комментарии живут только в `<script>`
  и в композаблах, `<template>` — чистая разметка.
- **Очевидное не комментируем** (правило владельца): комментарий — только неочевидное (готча библиотеки,
  решение владельца, ссылка на § документа). Пересказ кода — «собираем массив», «передаём проп»,
  «организм — секция» — шум, его не пишем.
- **Статика не ездит пропами** (правило владельца): список пунктов меню, набор советов, списки иконок —
  константы интерфейса — `shared/constants/ui.js` (пункты меню, советы). Пропом идёт только динамика
  (сезон из контента, ник игрока, валюта).
- **Реактивное от пропа — только `computed`:** массив, собранный один раз в setup (`const items = [{ label: props.nick }]`),
  держит значение на момент setup — имя в меню профиля не менялось после сохранения в модалке. Обёртка
  `computed(() => [...])` решает это.
- **`AAvatar`: `delay-ms` не передаём нулём.** reka-ui считает `delayMs === undefined` разрешением рисовать
  фолбэк, а `0` — falsy для его проверки `if (props.delayMs && isClient)`, поэтому `canRender` не поднимался
  никогда и аватар оставался пустым кругом. Проп объявлен `default: undefined` — не задавай ему `0`.
- **Заголовок вкладки — `useSeoTitle` в файле роута** (`app/pages/*.vue`): строка — статичный заголовок
  («Лобби»), функция — динамический («Партия: Анубис против Теслы» в `game.vue`). Композабл кладёт
  значение в `<title>` (`app/composables/ui/useSeoTitle.js`), базовый заголовок — в `app/app.vue`, шаблон —
  `app.head.titleTemplate`. **`definePageMeta({ title })` в head не выводится:** Nuxt файловую мету сам
  не читает (проверено — заголовок оставался пустым).
- **Шрифты — файлы проекта:** `public/fonts/*.woff2` + `@font-face` с `unicode-range` в
  `app/assets/styles.css`, прелоад в `app.head.link`, кэш папки — `routeRules['/fonts/**']`. Пакетов
  `@fontsource-variable/*` в проекте нет: браузер берёт шрифт по своему URL, и он виден в конфиге.
