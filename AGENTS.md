# UnPlugged — контекст проекта

Кэш для быстрого входа. Правь здесь же, если поменял архитектуру, инвариант или команду.
Правила — код `shared/`; интерфейс — `docs/terrain.md`. Файл уходит в каждый запрос, держим его сухим.

## 1. Что это

Браузерная настольная игра в духе Unmatched: hotseat за одним экраном, логика целиком в движке,
клиент только рисует и шлёт клики. Стиль доски примитивный: кружки, линии, сектора, текстуры.
Стек: Nuxt 4 (Vue 3 SFC), Tailwind 4, konva/vue-konva, vitest 4, pnpm; Node 24, Windows (PowerShell 5.1).

## 3. Движок

- **Хуки → фазы → действия.** `state.hook`: `gameStart`(1) → `turnStart`(2) → `turn`(3) → `turnEnd`(4) →
  `gameEnd`(5). Фазы хука `turn`: `handLimit` → `choose` → `movement` → `attack` → `defense` → `waiting`.
  Активна ровно одна фаза на игрока; она разрешает свои клики и объявляет `controls`.
- **Моменты** (`constants/moments.js`): `gameStart`(0), `turnStart`(1), `effect`(2), `picked`(3),
  `immediately`(4), `duringCombat`(5), `afterCombat`(6), `turnEnd`(7). Неизвестный — ошибка движка.
- **DSL:** `rules: [{ moment, when: [факты], any: [[факты]], then: [{ action, … }] }]` у карт и способностей.
  Факты — чистые функции от state, действие — универсальный экшен.
- **Правила одного момента независимы:** условия всех правил читаются до первого действия, потом
  выполняются их `then` по накопительному состоянию (`shared/rules/run.js`). Правило не может «включить»
  условие соседнего — иначе взаимоисключающие ветки одной карты срабатывали бы все подряд.
- **Экшены:** `SET_ACTIONS`, `SET_CARDS`, `SET_HEALTH`, `SET_FIGHTER_CELL`, `SWAP_FIGHTERS`,
  `SET_MOVEMENT`, `SET_COMBAT`, `SET_TARGETING`, `REVIVE_FIGHTER`, `PICK`, `FINISH_ACTION`, `RESIGN`.
  Клиент шлёт только `PICK`/`UI_*`.
- **Флаг «двигался в этом ходу»:** `fighter.movedThisTurn` ставит `SET_FIGHTER_CELL` при шаге по полю
  (не при расстановке), снимает начало хода; читается фактом `FIGHTERS { movedThisTurn }`.
  **Телепорт — не движение** (правило владельца): постановка бойца без прохода (обмен местами, возврат
  убитого, карта-телепорт) флаг не ставит — `SET_FIGHTER_CELL { teleport: true }`, `SWAP_FIGHTERS`
  передаёт признак сам.
- **Значения фактов в параметрах:** `FIGHTERS` отдаёт список объектов, `COMBAT { select }` — список id,
  а `areaOf`/`adjacentTo`/`fighterIds` ждут одного бойца. `findFighter` разбирает и строку, и элемент
  списка, и объект `{ fighterId }`; `SET_CARDS { cardIds }` так же принимает и ключи, и объекты карт
  из `CARDS`/`HAND` (`cardId` объекта). `COMBAT { select }` во время битвы читает **открытый бой**
  (`state.combat`), а `winner` — итог (`lastCombat`): без этого свойства «во время битвы» не видели бойцов.
- **Привязка карт:** карту убитого помощника нельзя объявить (атака, эффект, защита) —
  `hasFighterForCard` гейтит только объявление. Сброс и усиление (`bonus`) работают всегда: такие
  карты остаются в колоде как топливо, а не выпадают из игры.
- **Карты и бой — что умеет движок:** `HAND { of, min, max }` — число карт в руке, в том числе чужой
  («у противника нет карт» — `max: 0`); `COMBAT { bonus: 'opponent' }` — усиление карты боя стороны
  («значение моей карты равно усилению его атаки» — «Саван»); `SET_COMBAT { op: 'replaceDefense' }` —
  замена защиты (старая карта в сброс, второе обязательное окно защиты, автопас без карт, очередь боя
  не повторяет сыгранные шаги); `SET_REVEAL { op: 'bottom', of: 'self' }` — раскрытая карта под низ
  колоды; `ITEMS` / `SET_ITEM` — предмет-состояние для постоянных эффектов (пелена Анубиса).
- **Пустое перемещение не открывается** (решение владельца): если ни один боец из списка не может шагнуть
  ни на одну клетку, `SET_MOVEMENT open` не открывает окно — свойство карты просто не срабатывает, шаг
  эффекта отмечается сработавшим (`shared/actions/movement.js: movementHasDestination`). Так закрыт
  `deadlock`: обязательное окно «Метели из осколков» без клеток вставало намертво (сид 33, `ifrit` против
  `snow-queen`). У обычного перемещения окно всё же открывается, если в руке есть карта усиления (она
  добавляет радиус), а окно эффекта с исчерпанным радиусом закрывает «Закончить эффект»
  (`shared/phases/movement.js: closeWithoutMoves`).
- **Карта играется только со срабатывающим свойством** (требование владельца, §35): польза эффекта
  считается условиями движка (`bot/play/cards.js: effectWorth` — `fires` это число выполнившихся правил,
  `value` — польза по общей шкале), и карта с `known: true` и `fires === 0` получает **вес 0** — вето, как
  у «шага в никуда» (`bot/play/decide.js`). Вес сработавшей пользы — ген `effect` (1,5), отключается
  `BOT_EFFECT_WORTH=0`. Незнакомая карта без правил остаётся с прежним весом: новая механика не должна
  молча выпадать из игры. **Числа:** эффектов «впустую» 24% → 1% (720 партий), симметрия `greedy` против
  `greedy` — 50/50; замер — `bot/tools/waste.js`.
- **Темп по запасу колод — живая политика `trade`** (§36): у политики есть своё топливо (`fuel`) и запас
  колоды соперника (`rivalFuel`, `bot/play/decide.js: rivalDeckSize` — число открытое), и по их разнице
  считается `clock`: позади — давить (атака ×(1+1.2·дефицит), сближение выше), впереди — тянуть (добор
  дешевле, кайт разрешён). **Числа:** против `greedy` 50/50, против `aggressive` 51/48, медиана партии
  105 против 124, застреваний 3 против 60 на 2400. В браузере (`bot/play/ai.js: think`) перечисление идёт
  этой политикой; `greedy` остаётся чистым эталоном замеров. Замер — `bot/tools/stall.js`.
- **Оценка размена — утверждённый шаг, откату не подлежит** (§37–§38): в вес атаки добавлены шесть генов
  (`bot/play/policy.js: attackWeight`, у эталонов нулевые): `tradeCost` — усиление карты сгорает вместе с
  ней, цена `(value + bonus) / value`; `tradeRisk` — ожидание чужой атаки (`counting.js: expectedAttack`,
  без подглядывания в руку) против здоровья своего бойца, который может ударить (добивание риском не
  наказывается); `tradeWound` — материал сторон (`material: { mine, theirs }`, помощник весит половину):
  отставание поднимает цену атаки, перевес опускает; `tradeFuel` — при остатке колоды ≤3 добор дороже
  атаки; `tradeFuelSlope` — то же плавно, добавкой `slope / fuel`; `tradeCards` (§38) — `rivalHand` (чужие
  карты в руке, размер открыт) поднимает цену атаки, когда соперник не ответит картой, и опускает, когда
  рука полная; `tradeRivalFuel` (§39) — колода соперника в цене боя (`1 + gene · 0,4 · clamp((fuel − rivalFuel) / 8)`;
  знак проверен тестом — первая версия считала наоборот). **Числа:** `trade` против
  `greedy` 51/49, против `aggressive` 51/49, медиана 106, застреваний 1 из 2400. **Ценность карт:** карта без
  правил ценна как карта со свойствами (вес базовый, вето не ставится — `known: false`), а карта со
  свойствами ценна их срабатыванием (`known && fires === 0` → вес 0). Тесты —
  `tests/unit/bot/trade.test.js`, `tests/unit/bot/effect-valuation.test.js`.
  **`lastCombat.effects`** — разрешённая очередь свойств боя: что сработало, что отменили и от чего
  отказались. Заполняется при закрытии боя (потом `combat` снимается), поэтому статусы шагов после боя
  читают оттуда, а не по ссылке на `combat.effects`.
- **Очередь боя отвечает тому шагу, чьё окно открыто:** пауз в одном бою бывает несколько (своя карта
  и чужая), поэтому шаг ищется по `source` окна, а не «первый ждущий» (`shared/cards/run.js`) — иначе
  ответ уходит чужой карте и её `picked`-правило падает, например на изменении числа боя после расчёта.
- **«заморожен» — статус бойца** (`SET_STATUS`, факт `FIGHTERS { frozen }`, снимает `turnEnd`): движок
  закрывает ему шаг, телепорт и обмен (`SET_FIGHTER_CELL`, `movementFighterRejection`,
  `movementDestinations`). **Карты и умения, которые двигают бойца, обязаны сами проверять
  `frozen: false`** в условии окна — иначе окно откроется, а клик упадёт.
- **Дальность боя — только `attackRange`:** 1 — ближний, больше — дальник; признака `attackType`
  в игре нет (решение владельца). Дальник не бьёт «по области»: и он, и ближний достают по BFS-расстоянию
  не больше `attackRange` (`shared/helpers/combat.js`).
- **Умение-обмен («Серебряные башмачки» Дороти):** способность конца хода без автоматики и без окна
  с вопросом. Хук `turnEnd` объявляет фазу `choose`, правило на моменте `turnEnd` открывает окно цели
  по паре (Дороти и Тото в одной области, `required: false`), `choose` подсвечивает обоих и показывает
  текст способности, клик по любому выполняет `SWAP_FIGHTERS`, а отказ — общая кнопка «Завершить умение»
  (у необязательного окна свойства она называется «Закончить эффект»).
- **Окно выбора, открытое картой боя** (`SET_TARGETING` из правила боя — `immediately`, `duringCombat`,
  `afterCombat`): подсветку и клик ведёт фаза `defense` (`cardWindowOf`, `answerTargeting`) — так «Плата
  пеплом» выбирает, какого духа сжечь, а «Счёт ударов» — кого добить в области Ифрита. От обязательного
  окна отказаться нельзя (общей кнопки у него нет), от необязательного — можно: шаг очереди помечается
  `declined`, и бой доигрывается без свойства.
- **Максимальная автоматизация (правило игры):** безальтернативное решение делает движок, а не игрок —
  единственного кандидата окна он отмечает сам (`SET_TARGETING { auto: true }` → автовыбор), окно
  открывается только там, где выбор настоящий. Лишних кликов и подтверждений в игре нет.
- **Окно выбора показывает, а не спрашивает:** сверху подсказка, кандидаты подсвечены, у шага есть общая
  кнопка завершения («Закончить эффект» в окне свойства, «Закончить действие» в фазе). Вопросов «да или
  нет» и «выбрать или не выбрать» в интерфейсе нет: обязательное окно закрывается только выбором
  подсвеченной цели и кнопки не показывает, необязательное — закрывается общей кнопкой.
- **Случайность только через сид:** `state.settings.seed` + `state.rng` (LCG в `helpers/random.js`);
  `Math.random` в логике и генераторе запрещён.
- **`runAction` не меняет входное состояние:** кирпичи правят вложенные объекты на месте (`SET_HEALTH`
  вырезает убитого бойца из `player.fighters`), поэтому ход считается на форке
  (`shared/helpers/fork.js`) — «до» и «после» это разные объекты, и сравнивать их можно. Форк бесплатен
  (A/B в одном процессе: 2762 мс против 2771 мс на 200 партий, счёт побед тот же), а глубокий
  `structuredClone` всего состояния — 7,5×. Ветку, которую движок начнёт править, дописывают в форк:
  `tests/unit/core/immutability.test.js` перебирает легальные ходы и падает с именем изменившегося пути
  (`IMMUTABLE_SEEDS=40 IMMUTABLE_STEPS=200` — широкая проверка).
- **Правила партии** (`constants/rules.js`): 2 действия за ход, рука 5, лимит руки 7, истощение 2 урона,
  2–4 игрока, сквозь своих можно, сквозь врагов нельзя.

## 4. Стихии, старты, генератор — инварианты

- **Стихия = область.** `node.terrain` — строка или массив 2–3 стихий; клетка принадлежит всем своим
  областям (`sharesArea`). Палитра: `ice #CFE9F7`, `forest #349948`, `mountains #C2CBD8`,
  `lava #DF301C` (осознанно самый тёмный, текстура золотая `#F7C846`), `desert #F0DFA8`, `water #2E9FB8`.
- **Запасной стихии нет:** `terrainColor`/`terrainPattern` на неизвестном id бросают ошибку; клетка без
  стихии — ошибка контента, `createGame` проверяет стихии всех клеток при сборке.
- **Номерная клетка** = `heroStart: true` + `position` = место игрока (`seat + 1`); расстановка идёт по
  **области** номерной клетки, а не по списку стартовых.
- **Сторона места** (`constants/seats.js`): 1 слева, 2 справа, 3 сверху, 4 снизу, всегда; маркер смотрит наружу.
- **Генератор** (`helpers/mapGenerator.js`): поле из блоба, зоны 6–8, у каждой ≥4 клеток, стихии раздаются
  зонам без привилегий; связи покрывают поле, линия не идёт сквозь третью клетку; старт — у своей стороны,
  не дальше второй клетки от края (край по габариту поля); клетка 112 при шаге 170×158.
- **Карты:** фиксированных карт в контенте нет — поле собирает генератор по сиду партии
  (`mapId: 'generated'`, реестр `maps` пуст); клетка = `id, x, y, terrain, neighbors, heroStart, position`.

## 5. Клиент: доска

- Геометрия — только в `boardGeometry.js`; `Board.vue` — слои konva и ничего больше.
- Порядок слоёв клетки: база → сектора стихии → текстура → чёрные разделители → обводка → номер героя
  (только на расстановке).
- **Текстуры — растровые плитки** `public/patterns/*.webp` (`PATTERN_TILES`), так выбрал владелец: WebP 512
  (осыпь гор 256 — на 512 фактура смазывается), на клетке 88–161 px; плитка кладётся на клетку целиком и
  обрезается сектором. Плитка может быть темнее заливки палитры (лава) — тогда заливка работает только для
  подписи и легенды. Запасной векторный вариант остался у льда (`patternTextures.js`, `bake-patterns.mjs`) —
  доска его не рисует, пока у стихии есть плитка. Эталон вида — сами плитки `public/patterns/*.webp`.
- **Фактура не выдумывается**, источник — `tests/support/bake-tiles.mjs`: лёд — снежинки исходника с
  выравниванием блика, лава — кинцуги (фон в коричнево-красный, жилы золотые), лес — силуэты ветвей
  (чёрная тушь с прозрачностью) поверх заливки, пустыня — тёплый кроп акварели, горы — серая осыпь
  (крупный рендер вектора и уменьшение), вода — дуотон мраморной фактуры в цвета, подобранные ближе к
  исходнику. Параметры первых трёх сверены глазами: средний цвет и плотность трещин совпадают.
- **Новая стихия — только данные:** запись в `TERRAIN` + рецепт пекаря; логику править не нужно.
- **Цифры-id клеток скрыты** (`SHOW_CELL_IDS = false` в `boardGeometry.js`); для отладки — `true`.
- **Клики — на сцене**, не слушателями на конва-компонентах (иначе Vue ругается на fragment-корень):
  `stage.on('click tap', …)` + `clickTarget(event.target)` поднимается от фигуры к клетке по
  `cellName/cellId/fighterId/ownerId`. Слушатель вешается на `watch(stageRef)`, а не в `onMounted`:
  сцена живёт под `v-if="stageReady"` и появляется следующим рендером, где ссылка ещё пуста — тогда
  доска молча перестаёт кликаться целиком (тест `tests/unit/client/board-clicks.test.js`).
- **Партия — hotseat в браузере:** `useState('party:host')` + копия в `sessionStorage` (перезагрузка партию не
  убивает, закрытие вкладки — да); ход считается на клиенте (`runAction`), потом POST на сервер.
- **Режим против компьютера (`mode: 'vs_ai'`):** слоты с `control: 'ai'` ведёт клиент — он хост партии.
  Лобби помечает второй слот компьютером, `useGameAi` следит за состоянием и, пока действует `ai`-слот,
  играет за него тем же кодом, что и прогоны (`bot/play/ai.js` → `bot/play/decide.js` + `bot/play/search.js`), по одному
  действию через обычный `sendAction` — движок и сервер видят ту же последовательность, что при игре
  человека. Бюджет — 200 мс на ход (`AI_TIME_MS`), поиск за это успевает ~сотню доигрываний. Ядро решений
  обязано оставаться без `node:` и без `server/create.js`/`party.js`: этот код уходит в браузерный бандл
  (стережёт `tests/unit/bot/ai.test.js`), модуль бота подгружается динамически (`app/utils/aiPlayer.js`),
  поэтому hotseat его не тянет вовсе. `syncHotseat` в этом режиме экран не передаёт: за компьютером
  человека нет.
- **`/game` рендерится только на клиенте** (`routeRules` в `nuxt.config.ts`) — SSR давал ошибку гидратации.
- **Проекция:** `party.js` прячет чужое, `adaptPartyView.js` переименовывает `hook` в `phase`.

- Тестовый набор: 127 файлов / 1011 тестов. Полный прогон: 1008 зелёных, три известных падения —
  `tests/unit/client/board-geometry.test.js` про яркость лавы (0,217 против порога 0,2; это правка
  палитры в рабочем дереве) и два теста генератора «связи не проходят сквозь третьи клетки», которые
  **проходят в одиночном прогоне** (`tests/unit/content/generator.test.js` — 70/70): падают только под
  полной параллельной нагрузкой, то есть это флак прогона, а не логика. Сборка зелёная.
- **Новая страница в dev отвечает `Page not found`, пока у неё нет `ssr: false`.** Проверено на чистом
  кэше сборки: серверный рендер находит **только** `/`, хотя `pages:extend` перечисляет все маршруты, а
  `vue-router` их матчит — падение в `pages/runtime/plugins/router.js:afterEach` с пустым `to.matched`.
  Так живут `/game` и `/heroes/{id}`; отключение `payloadExtraction` и `@nuxt/test-utils/module` не
  помогает (`docs/ui-plan.md` §12, «Открыто»). «Перезапусти dev» тут не при чём.
- **`bfsDistance` без предела — это `Infinity`, а не `null`:** четвёртый аргумент — предел шагов, и с
  `null` условие `0 >= null` истинно, поэтому обход заканчивается сразу и расстояние всегда `Infinity`
  (на этом бот двигался вслепую: шаг в сторону врага ничем не отличался от шага в никуда).
- **Скрытое поле сырого состояния — не аргумент для бота.** `combat.attackValue`/`attackCard` лежат в
  состоянии открыто, но проекция (`party.js: projectCombat`) отдаёт их **только владельцу карты** до
  вскрытия (`reveal | resolve | close`), то есть живой защитник числа не видит. Политика обязана брать
  ожидание по остатку колоды соперника (`bot/play/counting.js`, `expectedAttack`), иначе метрики перестают
  быть честными; это уже случалось в §13 и закрыто тестом
  `tests/unit/bot/counting.test.js` («подмена скрытого числа не меняет выбор»).
- **Нечисловой предел шагов — это «по умолчанию», а не ноль.** `playDuel` берёт `maxSteps` из флагов CLI,
  и с `null` цикл `for (step = 0; step < maxSteps)` не делает ни шага (`0 < null` — ложь), поэтому партия
  сразу считалась незавершённой. Теперь `playDuel` сам приводит нечисловой предел к 400 — так же, как это
  делает любой другой потребитель отчёта.
- **Дневник обязан считать признаки теми же, что рантайм, а `chosen` — быть выбором бота.** `onStep`
  (`bot/play/duel.js`) отдаёт `payload` — действие **вместе с** `playerId`, поэтому сравнивать его со
  списком вариантов нужно без владельца (иначе индекс молча уходит в 0), а признаки действия для
  `qvalue`/`search` считаются по весам **жадного предлагателя**, а не по softmax модели (§23,
  `bot/learn/export.js: actionKey`/`PROPOSES_GREEDY`).
- **Лист на границе хода имеет смысл только в свой ход, а предел времени — и внутри роллаута.**
  `turnEnd`/`replyTurn` в чужом бою вырождаются в оценку текущей позиции (все варианты защиты равны),
  поэтому `searchAction` сам снимает их вне своего хода (`turnPlan` в ответе). Бюджет `SEARCH_TIME`
  проверяется и между доигрываниями, и на каждом шаге `rolloutEnd` (`clock`/`timedOut` в отчёте) — иначе
  один длинный роллаут пересиживает лимит; лимит итераций при заданном времени снимается сам (§25,
  `docs/student.md`).
- **Расширение вектора признаков действия ломает совместимость дневника и артефакта.** После блока
  признаков клетки (`bot/play/actionFeatures.js`, `ACTION_FEATURES` 20 → 23, §28) старые дневники
  переучивать нельзя (в них этих чисел нет), а старый артефакт грузится, но новые признаки не читает:
  дневник пересобирается, модель переучивается.
- Тесты героя удобно писать от фикстур `tests/fixtures/state.js`: `unit(id, cell, hp)` пишет `startHp = hp`,
  а `SET_HEALTH` не поднимает здоровье выше `startHp` — для тестов лечения задавай `startHp` больше
  текущего hp. Номер действия хода фиксируется состоянием ДО объявления карты (карта сама списывает
  действие), а при `actionsLeft: 0` фаза `choose` неактивна и `PICK` карты падает.

## 12. Клиент: правила компонентов и вёрстки

Конвенция владельца, соблюдаем без исключений (полностью — `.cursor/rules/code-style.mdc`):

- **Каталоги:** `app/components/atoms/` — универсальные кирпичики, имя всегда с `A` (`ALoader.vue`);
  `molecules/` — небольшие сборки из атомов (карточка героя, карточка режима); `organisms/` — секции страницы, внутри
  `organisms/lobby/` (`Menu`, `ExitScreen`), `organisms/layout/` (`Footer`, `ProfileBar`),
  `organisms/modals/` (`ProfileModal`, `TableSetupModal` — модалка настройки **общего стола**; у каждого
  режима своя, поэтому и имя по режиму, а не общее `Setup`). **Имя компонента = имя файла** (задано `components`
  в `nuxt.config.ts`; у `game/Board.vue` префикс задан руками — `<GameBoard>`).
- **Организм в корне всегда `<section>`**, не `<div>`; смысловые теги внутри остаются (`<nav>` в меню).
- **В `.vue` первым идёт `<template>`, вторым `<script>`**; блок `<style>` запрещён — стили только в
  `app/assets/styles.css` и классами Tailwind.
- **Атомы безстилевые, на `reka-ui`, по концепции preset/ui:** классов в разметке нет — только слоты
  пресета через `cn()`; пресеты — **по файлу на компонент** (`app/ui/button.js`, `app/ui/modal.js`, …),
  собираются в `app/app.config.js`, читает их `useUI(key)` из `app/composables/ui/useUI.js`
  (`appConfig.ui[key]`), локальные правки — проп `ui`. Склейка классов — только `cn` из `app/utils/cn.js`
  (там же зарегистрированы группы наших fluid-утилит и конфликт `w`/`h` с `size`: **правка `ui` обязана
  перекрывать пресет** — иначе квадрат пресета (`size-36`) побеждал правку `h-48 w-192` порядком утилит
  в CSS и размер приходилось помечать `!`; стережёт `tests/unit/client/cn.test.js`). Состав атомов: `AScroll` (общий скролл,
  применяется и внутри других атомов), `AModal` (по имени: `openModal(name, payload)`,
  `closeAllModals()`), `AButton`, `ASelect`, `ADropdown`, `ARadio`, `ARadioGroup`, `ACheckbox`,
  `ACheckboxGroup`, `AAvatar`, `APicture`, `ATabs`, `ATooltip`, `ASwitch`, `ALoader`.
- **Композаблы ui — в `app/composables/ui/`** (`useUI`, `useModal`): то, что про атомы и пресеты, лежит
  отдельно от логики приложения (`useProfile`, `useLobbyBoot`, `useGameView`).
- **Перетаскивание — одно на всю игру** (`useDraggable` + `useSortable`, `app/composables/`): указатель
  с порогом начала (`threshold`), `axis`, `clamp`, клавиатура, отмена по `Esc`; движение и отпускание
  указателя ловятся **на `document`**, пока идёт перетаскивание (на элементе они теряются, как только
  указатель ушёл с него, — перетаскивание тогда выглядит «не работает»). Порядок списка —
  `handleProps`/`targetProps` (метка `data-sortable-index`), `move`/`moveBy`, режимы `insert` и `swap`.
  **Колбэки — `(значение, context)`, позиция первой:** цель под курсором лежит в `context.pointer`, и
  поиск её в первом аргументе уже ломал перестановку молча. Порядок считает чистая функция `reorder` из
  `app/utils/sortable.js` (под тестом), перестановка указателем — `tests/unit/client/sortable-dom.test.js`
  (happy-dom, элемент обязан быть в документе). `touch-none` на блоке — забота потребителя.
- **Время — только от метки дедлайна** (`useTimer`): `setInterval` дрейфует и замирает в фоновой вкладке,
  поэтому показываем `deadline - now`, а тик лишь пересчитывает показ. **Время не пишем в `state`** — он
  воспроизводим по сиду, и `Date.now()` внутри правил сломал бы и бота, и тесты на неизменность.
- **Поле ввода — атом `AInput`** (`label`, `hint`, `error`, `numeric`, слоты `prev`/`next`), как `AScroll`
  для скролла: свой `<input>` руками не пишем. Ошибка поля связана с ним через `aria-describedby`.
- **Реестр модалок — модульный `ref`, а не `useState`:** модалки открывает клиент, а `useState` через
  `runWithContext` в Nuxt 4 возвращал промис и ронял рендер (`Cannot read properties of undefined
  (reading 'includes')`); состояние реестра живёт до перезагрузки страницы.
- **В `app.config.js` импорты только через alias** (`~/ui/button.js`): относительные пути в dev-сборке
  Nitro разрешались от корня диска (`Cannot find module 'C:\app\ui\avatar.js'`).
- **`APicture` — без форматов:** растровые файлы у нас всегда WebP, поэтому art-direction по брейкпоинтам
  (`lg:src="…"`, имена из `ui.screens`), прелоад вешается `media`-ссылками (браузер тянет только текущее
  разрешение), по умолчанию `loading="lazy"`.
- **SVG живут в `app/svg/`** (`app/svg/brand/logo.svg`) и импортируются как компоненты через
  `vite-svg-loader`; в `public/` остаются только те, что браузер забирает по URL (фавиконки и иконки
  приложения). Файлы знака собирают `tests/support/bake-brand.mjs` и `bake-wordmark.py`.
- **Компонент ради двух тегов не заводим:** иконка или логотип, обёрнутые в ссылку, — это разметка
  страницы (`<NuxtLink><BrandLogo /></NuxtLink>`), а не компонент. Компонент оправдан, когда в нём логика,
  слоты или несколько осмысленных частей.
- **Всё кликабельное — «рука»:** одно общее правило в `app/assets/styles.css` (`button`, `[role='button']`,
  `select`, `summary`, `a[href]`, `label[for]`; `:disabled` — «нельзя»), в компонентах `cursor-pointer`
  не дублируем.
- **Проектные композаблы в новых файлах импортируем явно** (`~/composables/...`): `pnpm dev`, поднятый до
  появления файла, его в автоимпортах не знает и падает в рантайме (`useProfile is not defined`), при этом
  сборка остаётся зелёной.
- **Комментариев в разметке нет** (правило владельца): в `.vue` комментарии живут только в `<script>`
  и в композаблах, `<template>` — чистая разметка.
- **Очевидное не комментируем** (правило владельца): комментарий — только неочевидное (готча библиотеки,
  решение владельца, ссылка на § документа). Пересказ кода — «собираем массив», «передаём проп»,
  «организм — секция» — шум, его не пишем.
- **Статика не ездит пропами** (правило владельца): список пунктов меню, набор советов, списки иконок —
  константы интерфейса — `shared/constants/ui.js` (пункты меню, советы). Пропом идёт только динамика
  (сезон из контента, ник игрока, валюта).
- **Реактивное от пропа — только `computed`:** массив, собранный один раз в setup (`const items = [{ label: props.nick }]`),
  держит значение на момент setup — имя в меню профиля не менялось после сохранения в модалке. Обёртка
  `computed(() => [...])` решает это.
- **`AAvatar`: `delay-ms` не передаём нулём.** reka-ui считает `delayMs === undefined` разрешением рисовать
  фолбэк, а `0` — falsy для его проверки `if (props.delayMs && isClient)`, поэтому `canRender` не поднимался
  никогда и аватар оставался пустым кругом. Проп объявлен `default: undefined` — не задавай ему `0`.
- **Заголовок вкладки — `useSeoTitle` в файле роута** (`app/pages/*.vue`): строка — статичный заголовок
  («Лобби»), функция — динамический («Партия: Анубис против Теслы» в `game.vue`). Композабл кладёт
  значение в `<title>` (`app/composables/useSeoTitle.js`), базовый заголовок — в `app/app.vue`, шаблон —
  `app.head.titleTemplate`. **`definePageMeta({ title })` в head не выводится:** Nuxt файловую мету сам
  не читает (проверено — заголовок оставался пустым).
- **Шрифты — файлы проекта:** `public/fonts/*.woff2` + `@font-face` с `unicode-range` в
  `app/assets/styles.css`, прелоад в `app.head.link`, кэш папки — `routeRules['/fonts/**']`. Пакетов
  `@fontsource-variable/*` в проекте нет: браузер берёт шрифт по своему URL, и он виден в конфиге.
