# Проверки

Чем проверяем этот проект, что означают числа в отчётах и как читать падения. Какой объём проверок требует
правка — таблица «тип правки → чем проверяем» в `.docs/workflow.md`. Стиль и запреты кода — не здесь:
`.docs/rules/code-style.mdc`.

## Что и чем проверяем

| Уровень                 | Чем                                                       | Когда                                        |
| ----------------------- | --------------------------------------------------------- | -------------------------------------------- |
| unit-тесты              | `tests/unit/**`, vitest 4                                 | логика: `shared/`, `server/`, `bot/`, `app/` |
| сценарии                | `tests/scenarios/**` — те же тесты, играют партию целиком | движок, фазы, контент                        |
| прогон бота             | `bot/tools/run.js`, `bot/tools/hotseat.js`, `test:matrix` | движок, генератор, контент, бот              |
| клиентский прогон стола | `tests/scenarios/hotseat-ui.test.js` + `$env:UI_SEEDS`    | сессия партии, панели, клики по подсветке    |
| браузерный обход        | `tests/support/hotseat-browser.mjs`                       | когда нужна живая канва, а не happy-dom      |
| сборка                  | `node node_modules\nuxt\bin\nuxt.mjs build`               | системная правка, конфиг сборки, зависимости |

## Чего в проекте нет

- **Нет e2e-раннера.** `@playwright/test` и `playwright.config.*` в проекте нет; `playwright-core` стоит
  только ради `tests/support/hotseat-browser.mjs`, и это обход партии, а не набор проверок.
- **Нет eslint.** Стиль держится правилами `.docs/rules/code-style.mdc` и `prettier`
  (`node node_modules\prettier\bin\prettier.cjs --write <файлы…>`, он же `pnpm format`).
- **Нет CI.** Прогон запускает человек локально; «зелено» — это вывод на этой машине, а не статус пайплайна.
- **Вёрстку и стили агент не проверяет вообще** (требование владельца, `AGENTS.md` §6): шаблоны, классы,
  цвета, размеры, отступы, шрифты, флаги отрисовки смотрит владелец глазами. Сломанный шаблон видно по
  неотрисованной странице, а не по упавшему тесту.

## Unit-тесты

`vitest.config.ts`: `include: ['tests/**/*.test.js']`, `environment: 'node'`, `globals: false` — поэтому
`describe`/`it`/`expect` импортируются из `vitest`, а не берутся из глобалов. Клиентские файлы начинаются
строкой `// @vitest-environment happy-dom` (весь `tests/unit/client/**` и `tests/scenarios/hotseat-ui.test.js`).

| Папка                                           | Что покрывает                                                         |
| ----------------------------------------------- | --------------------------------------------------------------------- |
| `tests/unit/core/`                              | движок: `runAction`, ходы, `immutability`, телепорт, временные стихии |
| `tests/unit/phases/`                            | фазы: атака, защита, лимит руки, расстановка, окна битвы              |
| `tests/unit/cards/`                             | карты по одному правилу (`ifrit_14.test.js`) и разборы колод целиком  |
| `tests/unit/skills/`                            | умения героев: по файлу на героя плюс `run.test.js`                   |
| `tests/unit/content/`                           | схемы контента: имена, типы, колода, `generator.test.js`, подсказки   |
| `tests/unit/client/`                            | композаблы и компоненты под happy-dom                                 |
| `tests/unit/bot/`                               | политика, поиск, оценка, счёт карт, метрики                           |
| `tests/unit/party/`, `tests/unit/party.test.js` | сборка партии и проекция `view`                                       |

Один файл — одна команда:

```powershell
node node_modules\vitest\vitest.mjs run tests/unit/client/card-text.test.js --pool=threads
```

- `pnpm exec` не используется: PowerShell 5.1 в песочнице его не проводит, а бинарь запускается напрямую
  (`node node_modules\vitest\vitest.mjs` — тот же запуск, без оболочки pnpm; разбор — `.docs/onboarding.md` §4).
- `--pool=threads` — режим пула, которым гоняются все прогоны проекта (`AGENTS.md` §5).
- Весь набор: `node node_modules\vitest\vitest.mjs run --pool=threads` (он же `pnpm test`); наблюдение —
  `pnpm test:watch`.
- Длина серий задаётся переменными окружения: `$env:FUZZ_SEEDS='200'` — сколько партий в фаззинге сценариев,
  `$env:IMMUTABLE_SEEDS='40'; $env:IMMUTABLE_STEPS='200'` — широкая проверка неизменности состояния.

## Прогон бота

`bot/tools/sweep.js` — не команда, а общий код серии: его зовут `run.js`, `matrix.js` и тесты из
`tests/scenarios/*.test.js`, поэтому отчёт у них одинаковый.

| Файл                   | Что меряет                                                                                                                   | Запуск                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `bot/tools/run.js`     | фаззинг дуэли: падения, тупики, пустые действия, покрытие колоды                                                             | `node bot/tools/run.js --seeds=200 --heroes=anubis,tesla`  |
| `bot/tools/hotseat.js` | фаззинг стола на 2–4 человек и утечки проекции                                                                               | `node bot/tools/hotseat.js --games=500`                    |
| `bot/tools/matrix.js`  | матрица матчапов и сводка по героям (готовый markdown)                                                                       | `pnpm test:matrix -- --games=200`                          |
| `bot/tools/stall.js`   | длина партии и её конец: убийством или истощением                                                                            | `node bot/tools/stall.js --games=40 --policy=search`       |
| `bot/tools/waste.js`   | эффектные карты «не впустую»: сколько правил сработало                                                                       | `node bot/tools/waste.js --heroes=ifrit,snow-queen`        |
| `bot/tools/stats.js`   | вклад политики по героям и профиль героя: карты, умение, предметы, колода, матчапы; флаг `--cards` — таблица по каждой карте | `node bot/tools/stats.js --policy=search --policy-b=trade` |
| `bot/tools/think.js`   | проба хода с бюджетом времени (тот же код, что в браузере)                                                                   | `node bot/tools/think.js --time=1000 --samples=5`          |
| `bot/tools/tuner.js`   | подбор весов политики координатным спуском                                                                                   | `node bot/tools/tuner.js --minutes=5`                      |

- Политика — флагом `--policy=` (второй игрок — `--policy-b=`): `random` — фаззинг, `search` — живой бот
  с выученным листом, `trade` — живая политика браузера. `greedy` из команд выведен (решение владельца):
  он остался внутренней базой весов, метрики читают по `search`. Опечатка в имени политики роняет прогон,
  а не превращается тихо в `random`.
- Сид воспроизводим: `--seed=33` разбирает одну партию один в один, в отчёте есть лог последних действий.
- Код возврата: находки → `[exit code: 1]`; чистый прогон печатает «находок нет: все партии дошли до конца».

### Что означают метрики

| Метрика                                | Смысл                                                                                                             |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `до конца N`                           | партии с исходом; победитель есть всегда                                                                          |
| `победы: <герой> N (P%)`               | винрейт героя. На `random` это не баланс, а проверка, что победа достижима за обе стороны                         |
| `не завершились` / `stuck`             | партия не уложилась в лимит шагов; свойство бота, прогон не роняет — чаще «длинная», чем «тупик»                  |
| `тупиков` / `deadlock`                 | движок ждёт ход, а сыграть нечего (например, обязательное окно без вариантов) — находка                           |
| `падений` / `crash`, `invalid`         | исключение или нарушенный инвариант — находка                                                                     |
| `пустых действий` / `noop`             | действие не изменило состояние; в отчёт идёт, прогон не роняет                                                    |
| `утечек проекции` / `view`             | смотрящий увидел чужую руку, колоду или расстановку — находка                                                     |
| `медиана` и `средняя длина`            | сколько действий (кликов) длится партия; длину печатают `stall.js` и `waste.js`                                   |
| `покрытие: сыграно карт N из M`        | где бот ещё не искал баги; «ни разу не сыграны» — мёртвый груз колоды или непроверенная ветка                     |
| `конец партии: убийством / истощением` | чем решилось: боем или пустой колодой (убийство первым бойцом — отдельное число)                                  |
| коридор винрейта                       | 40–60% против среднего по пулу, отдельный матчап 30–70%; выход помечается `!`, числа — `.docs/hero-balance.md` §5 |

## Клиентский прогон стола

`tests/scenarios/hotseat-ui.test.js` — тот же стол, но ведёт его настоящий клиент: `useGameSession` с
серверной проекцией, ходы — клики по подсветке, рядом живут настоящие панели (`tests/support/hotseat-ui.js`).
Находки: `empty` (пустой экран), `silent` (кнопка-пустышка), `acting` (экран не тому человеку), `render`,
`console`, `crash`; `stuck` попадает в отчёт.

По умолчанию один сид — он же идёт в `pnpm test`. Длинная серия:

```powershell
$env:UI_SEEDS='20'; node node_modules\vitest\vitest.mjs run tests/scenarios/hotseat-ui.test.js --pool=threads
Remove-Item Env:UI_SEEDS
```

Сиды идут с 1 до `UI_SEEDS`, таймаут теста — 180 с, поэтому десятки сидов это уже минуты.

## Браузерный обход

```powershell
node tests/support/hotseat-browser.mjs --steps=60 --seed=5 --headful
```

- Флаги: `--seed`, `--players`, `--steps`, `--headful`, `--built` (взять готовую `.output` вместо dev).
- Браузер: Chrome или Edge; свой путь — `CHROME_PATH`.
- Приложение: если на `GAME_URL` (по умолчанию `http://localhost:3000`) уже что-то отвечает, скрипт его не
  трогает; иначе поднимает `pnpm dev`.
- Скриншоты каждого шага — `.workbuddy/browser/<сид>/`; папка в `.gitignore`.
- Находка: ошибки консоли и падения страницы, клик без последствий и без ответа, отсутствие подсказки там,
  где движок ждёт ход, потеря связи с партией (404), зависание.

## Сборка

```powershell
node node_modules\nuxt\bin\nuxt.mjs build   # ожидаем BUILD_EXIT=0; то же: pnpm build
```

5–6 минут на полную сборку. Гоняем только под системную правку (движок, генератор, контент-схемы,
`nuxt.config.ts`, зависимости) или по прямой просьбе владельца; после косметики сборка — выброшенное время.
`.output/` в `.gitignore`, результат сборки в дифф не попадает.

## Объём: сколько гонять

- **Полный набор не гоняют после каждой правки** и не гоняют «на всякий случай»: логика — тесты затронутого
  файла.
- Вёрстка, стили и тексты — проверок нет вообще (смотрит владелец).
- Системная правка — движок, генератор, контент-схемы, конфиг сборки, зависимости — полный набор + фаззинг +
  сборка.
- Точная таблица «тип правки → что запускаем» — `.docs/workflow.md`.

## Если прогон упал

1. **Прочитать имя упавшего теста**: vitest печатает файл и название `it`, а в названии уже есть герой и сид
   («ifrit против snow-queen, сид 33: …»). Сообщение движка в отчёте и есть ответ, что сломалось.
2. **Воспроизвести один файл**, а не набор — той же командой с путём файла.
3. **Партию — по сиду:** `node bot/tools/run.js --seed=33 --heroes=ifrit,snow-queen` (лог последних действий
   в отчёте), стол — `node bot/tools/hotseat.js --seed=18 --players=4`, клиент — `$env:UI_SEEDS='18'`
   прогонит сиды 1…18, в выводе ищите нужный.
4. **Падает только под полным прогоном** — повторить файл в одиночку: в наборе есть известный флак (ниже).
5. **Чинить причину, а не проверку**: `skip`/`only`, ослабленное ожидание и удалённый тест — не починка. В
   отчёте писать, что не запускалось и почему.
6. **Код возврата** `[exit code: 1]` у vitest, `run.js` и `hotseat.js` — это находка, а не сбой оболочки.

## Известный долг

- **Закрытая находка становится тестом и остаётся навсегда.** `tests/scenarios/seed-regressions.test.js`
  держит сид 33 (`ifrit` против `snow-queen`: обязательное окно без клеток вставало намертво),
  `tests/scenarios/hotseat.test.js` — сид 18 (чужие помощники заняли область расстановки). Такой тест не
  удаляется «за ненадобностью»: он и есть замок на починенное.
- **Известный флак набора:** два теста генератора «связи не проходят сквозь третьи клетки»
  (`tests/unit/content/generator.test.js`) падают только под полной параллельной нагрузкой и проходят в
  одиночном прогоне (70/70). Это флак прогона, а не логика: ответ — одиночный файл.
- **Устаревшее ожидание — не долг, а ошибка.** Сначала решается, что верно (код или ожидание), потом правится
  одно место; тест не подкручивается под код молча.
- **Счётчики в документации — снимок на дату записи.** Числа вида «столько-то файлов и тестов» живут дольше,
  чем набор: это ориентир, а не договор.
