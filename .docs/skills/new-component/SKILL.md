# Компонент

## Когда брать

- новый компонент: атом, молекула, организм-секция, панель экрана;
- новый экран или крупная часть экрана партии;
- доработка существующего компонента: новый режим, состояние, проп.

## Порядок работы

1. **Понять место.** Какой экран или секция его использует, сколько раз, какие состояния (данные, пусто,
   ошибка, загрузка). Компонент ради двух тегов — это разметка страницы, а не компонент
   (`.docs/rules/code-style.mdc`).
2. **Определить уровень по месту, а не по вкусу:**
   - атом — `app/components/atoms/`, на `reka-ui`, имя всегда с `A` (`AButton.vue`, `AScroll.vue`);
     классов в разметке атома нет — только слоты пресета через `cn`;
   - молекула — `app/components/molecules/<раздел>/Name.vue`, без префикса;
   - организм — `app/components/organisms/<раздел>/Name.vue`, корневой тег `<section>` первым.
3. **Имя = имя файла** (`GameScreen.vue` → `<GameScreen>`); префикс есть только у атомов и у доски
   (`Game` → `<GameBoard>`).
4. **Структура файла:** `<template>` первым, `<script setup>` вторым, блока `<style>` нет; классы Tailwind —
   прямо в разметке; комментариев в шаблоне нет.
5. **Проверить, есть ли уже кирпичик.** Атомы: `AButton`, `ASelect`, `ADropdown`, `ARadio`,
   `ARadioGroup`, `ACheckbox`, `ACheckboxGroup`, `AAvatar`, `APicture`, `ATabs`, `ATooltip`, `ASwitch`,
   `ALoader`, `AInput`, `AModal`, `AScroll`, `AHexagon`. Свой `<input>`, селект, модалка и скролл руками
   не пишутся.
6. **Пресет — только если стилевой набор повторяется:** `app/ui/<атом>.js` + сборка в `app/app.config.js`
   (импорт через alias `~/ui/button.js`), чтение — `useUI(key)` из `app/composables/ui/useUI.js`, склейка
   классов — только `cn` из `app/ui/cn.js`. Одиночная разметка классы в пресет не выносит; правка пресета
   пропом `ui` обязана его перекрывать.
7. **Откуда состояние.** Общее состояние компонент читает композаблом сам: `useGameSession`,
   `useProfile`, `ui/useModal`, `ui/useToast`. Проп — только меняющийся вход (`:stage-label`, `:season`,
   `:interactive`); состояние партии через панели не протягивают.
8. **Импорт явный:** `import AButton from '~/components/atoms/AButton.vue'`, композаблы — `~/composables/...`;
   автоимпорта компонентов в проекте нет.
9. **Данные и картинки.** Картинка — только `APicture` (art-direction через `lg:src`, `loading="lazy"`);
   чистого `<img>` в разметке нет. SVG — файл в `app/svg/` и импорт как компонента.
10. **Где живёт остальное.** Константы — `app/constants/` (`cards.js`, `health.js`, `animation.js`,
    `tooltips.js`, `colors.js`, `heart.js`), в композаблах их нет. Логика — `app/composables/`: `game/` —
    правила и состояние партии, `ui/` — интерфейс, `animations/` — движение. Каталога `app/utils/` нет.
11. **Экран** дополнительно: страница в `app/pages/`, маршрут — в `app/router.options.js`, заголовок
    вкладки — `useSeoTitle` в файле роута.

## Проверки

- Вёрстка, классы, размеры и тексты — **без прогонов**: их смотрит владелец глазами (`AGENTS.md` §6).
- Тронута логика (композабл, пресет, `cn`, чистые функции) — тест затронутого файла:
  `node node_modules\vitest\vitest.mjs run tests/unit/client/<файл> --pool=threads`.
- Тронут `app/ui/cn.js` или конфликт `size`/`w`/`h` — `tests/unit/client/cn.test.js`.

## Отчёт

- какие файлы созданы или изменены и почему выбран этот уровень;
- что взято из существующих атомов и пресетов, что написано своё и почему;
- откуда читается состояние и какие пропсы остались; что запущено и что не запущено и почему.
