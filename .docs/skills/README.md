# Скилы

Скил — пошаговая процедура под один тип задачи: что прочитать, в каком порядке делать, что проверить и
как отчитаться. Скил **не повторяет правила кода**: они живут в `.docs/rules/*.mdc`, в
`.docs/review-rules.md` и в доках своих фич (`.docs/ui.md`, `.docs/engine.md`, `bot/README.md`). Скил
говорит, какие из них важны здесь и в каком порядке их читать.

## Правило входа

- Задача совпала со скилом — первый ответ агента начинается словами «читаю
  `.docs/skills/<name>/SKILL.md`», и только потом план и правки.
- Один запрос — один скил. Задача шире (герой и его экран, замер и правка движка) — шаги двух скилов,
  названных явно, а не один сборный.
- Скил — не догма: если по коду нужно иначе, отклонение объясняется в ответе, а не делается молча.
- План и явное «делай» скил не отменяет (`AGENTS.md` §2): сначала файлы и проверки, потом код.

## Формат

```
.docs/skills/<kebab-name>/
  SKILL.md      # frontmatter name/description + разделы
```

```yaml
---
name: new-component
description: Одна строка: когда брать.
---
```

- `name` = имя каталога (`pnpm docs:check` сверяет), `description` — одна строка «когда брать».
- Разделы: «Когда брать», «Порядок работы», «Что смотреть в проекте», «Проверки», «Отчёт».
- Пути — от корня репозитория (`.docs/engine.md`, `shared/core.js`), команды — только реальные из
  `package.json` и `AGENTS.md` §5–§6.
- Чужое правило в скиле не пересказывается: стоит путь. Дубликат правила — ошибка, а не удобство.

## Каталог

| Скил | Когда брать |
| --- | --- |
| `new-hero` | новый герой целиком: пак, колода, паспорт, тесты |
| `new-card` | новая карта или правка её текста и числа |
| `engine-change` | правка движка: хук, фаза, действие, факт, окно |
| `new-component` | новый компонент, молекула, организм или экран |
| `bot-measure` | замер силы героев и политик, разбор находок бота |
| `bot-balance` | переучивание бота, статистика побед по всем героям, рекомендации по коридору |
| `audit` | аудит перед сдачей: что проверить целиком |
| `code-review` | ревью диффа по правилам проекта |

## С чего начать

| Что делаешь | Первый скил | Дальше читать |
| --- | --- | --- |
| героя, карту | `new-hero`, `new-card` | `.docs/hero-algorithm.md`, `.docs/content-ip.md` |
| движок | `engine-change` | `.docs/engine.md`, `.docs/rules/internal-logic.mdc` |
| клиент | `new-component` | `.docs/ui.md`, `.docs/rules/code-style.mdc` |
| замер бота | `bot-measure` | `bot/README.md`, `.docs/hero-balance.md` |
| переучивание и коридор | `bot-balance` | `.docs/hero-balance.md` §2, §4, §5, `.docs/hero-bot-axes.md` |
| сдачу | `audit` | `.docs/rules/audit.mdc` |
| ревью | `code-review` | `.docs/review-rules.md`, `.docs/review-ignore.txt` |

## Кто правит

- Скилы ведёт владелец проекта, как и остальную `.docs/`.
- Агент меняет скил только по явной просьбе в текущей задаче; заявка человека — «какой шаг сработал не
  так и что было в коде».
- Устаревший шаг переписывается, а не обрастает оговорками: история живёт в git.
