# Статусы бойца

Состояние бойца на поле: «заморожен» и всё, что появится дальше. Не карта и не предмет — статус живёт на
самом бойце и снимается по своему сроку или правилом карты.

Реестр — **`shared/constants/statuses.js`**: одно место, где у статуса есть id, название, иконка, описание
и **что он запрещает**. Из него берут все трое: движок (что вообще можно поставить), интерфейс (чем
рисовать) и контент (какой id писать в правиле карты).

| id | Название | Иконка | Что делает | Запрещает |
| --- | --- | --- | --- | --- |
| `frozen` | Заморозка | `material-symbols:ac-unit` (снежинка, не та, что у осколков) | «Оцепенение» Снежной королевы: при 4+ осколках в её сбросе атакующий заморожен | `move` (шаг и принудительное перемещение), `teleport` (перенос без прохода, обмен) |

## Срок живёт на экземпляре, а не в реестре

Один и тот же `frozen` бывает «до конца текущего хода» и «до конца своего хода», поэтому срок ставится
вместе со статусом: `fighter.statuses[id] = { until }`. В реестре срока нет — там только смысл статуса.

| `until` | Когда снимается |
| --- | --- |
| `turnEnd` (по умолчанию) | на ближайшем конце хода, чей бы он ни был — это «до конца текущего хода» |
| `ownerTurnEnd` | в конце хода **владельца бойца** — «до конца его хода»; поставленный в чужой ход переживёт его |

`until` проверяется `SET_STATUS` (`STATUS_UNTIL`), снимает срок `releaseStatuses`
(`shared/lifecycle/turnEnd.js`). Любое другое условие («пока стоит на льду», «до конца круга») снимает
**само правило** действием `SET_STATUS { value: false }` — движку для этого ничего не нужно.

Новый срок — это запись в `STATUS_UNTIL` и одна ветка в `releaseStatuses`: два места, оба в файле реестра.

## Как ставить из карты

Правило любого момента (`immediately`, `duringCombat`, `afterCombat`, `turnEnd`, …):

```js
{ action: 'SET_STATUS', fighterIds: '$foe', status: 'frozen', value: true }
{ action: 'SET_STATUS', fighterIds: '$foe', status: 'frozen', value: true, until: 'ownerTurnEnd' }
{ action: 'SET_STATUS', fighterIds: '$foe', status: 'frozen', value: false }   // снять досрочно
```

`fighterIds` — id бойца, список, объект факта (`{ fighterId }`) или переменная условия (`'$foe'`):
разбирает само действие (`shared/actions/status.js`).

**Карты и умения, которые двигают бойца, обязаны сами проверять статус** в условии окна
(`FIGHTERS { frozen: false }`) — иначе окно откроется, а клик упадёт с «боец заморожен». Так уже сделано у
«Пути на закат», «Тото отвлекает» и «Серебряных башмачков».

## Что движок закрывает сам

Запреты читаются **из реестра**, а не из конкретного поля: `blockingStatus(fighter, 'move' | 'teleport')`
(`shared/constants/statuses.js`). Им закрыты:

| Механика | Где |
| --- | --- |
| постановка бойца на клетку, включая телепорт и обмен (`SWAP_FIGHTERS` идёт через `teleport: true`) | `shared/actions/fighter.js` |
| открытие перемещения этим бойцом и принудительный перенос чужим эффектом | `shared/helpers/turn.js: movementFighterRejection` |
| подсветка клеток шага | `shared/helpers/turn.js: movementDestinations` |

Условия в правилах читают то же состояние фактом `FIGHTERS { frozen }` (`shared/facts/fighters.js`).

**Старый вид записи** (`fighter.frozen = true` прямо на бойце) читается наравне с новым и снимается как
`turnEnd`: партии в памяти сервера и в `sessionStorage` могли пережить перезапуск.

## Как это видно в интерфейсе

- **На доске — плашки у фишки** (`app/composables/ui/useBoardMap.js: fighterStatusBadges`): слева-снизу,
  друг над другом (первый ближе к сердцу — сердце торчит справа-снизу, место зеркально ему). Наведение на
  плашку показывает подсказку с описанием статуса; **в подсказке самого бойца статусов нет** (правило
  владельца). Иконка на доске рисуется геометрией (снежинка из трёх лучей) — масштабируется вместе с полем
  и не требует шрифтов.
- **В окне героя** (`app/components/molecules/game/HeroInfo.vue`): строка «Статусы» — вкладка «Герой» для
  самого героя и вкладка «Помощники» для выбранного помощника. Названия — через запятую (иконки живут на
  доске, а статусов может стать много). Нет статусов — строки нет вовсе.

## Как добавить статус

1. Запись в `STATUSES` (`shared/constants/statuses.js`): `id`, `title`, `icon` (имя iconify, коллекции
   `lucide`/`game-icons`/`material-symbols`), `text`, `forbids` (`move` / `teleport`).
2. Правило карты ставит его `SET_STATUS` (см. выше) — валидация, сроки и запреты подхватятся сами.
3. Плашка на доске появится сама (снежинка из трёх лучей: `useBoardMap: statusGlyphArms`; своя фигура —
   там же), строка в окне героя — тоже.

**Чего в реестре быть не должно:** срока. Он принадлежит экземпляру (`until`), потому что один статус
живёт по разным условиям.

## Что осталось открытым

- **Статусы игрока** (снижение лимита руки, постоянные эффекты) — это **не** статусы бойца: им нужен свой
  слой, и это отдельное решение владельца.
- **Бот** знает про «заморожен» признаком `frozen` в `bot/play/value.js` (читает через `hasStatus`); новые
  статусы нужно добавлять туда же, иначе он их не увидит.

Стерегут `tests/unit/content/statuses.test.js` (реестр, постановка, сроки, запрет),
`tests/unit/client/board-map.test.js` (плашка и подсказка) и `tests/unit/skills/snow-queen.test.js`
(«Оцепенение» снимается концом хода).
