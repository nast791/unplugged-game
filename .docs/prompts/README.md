# Промпты для типовых задач

Скелет запроса, который не забывает критерий готовности и границы. Одна карточка — одна задача: две
задачи в одном запросе дают широкий дифф и слабую проверку.

## Как пользоваться

1. Выбери карточку по типу задачи. Заполни `[...]` фактами: файл, сид, слой, имена карт. «Сделай
   красиво» — не критерий.
2. Если задача совпадает со скилом — назови его прямо: `.docs/skills/<name>/SKILL.md`
   (`new-hero`, `new-card`, `new-component`, `engine-change`, `bot-measure`, `audit`, `code-review`).
3. Отправь. Первый ответ — план, код — после «делай».

## Карточки

| Карточка | Когда |
| --- | --- |
| `bugfix.md` | что-то сломано, есть сид или шаги воспроизведения |
| `feature.md` | новая возможность или заметная доработка |
| `refactor.md` | структура без смены поведения |
| `review.md` | ревью диффа: что не так и что сделать |
| `audit.md` | аудит фичи или проекта после серии правок |

## Шаблон ответа агента

| Шаг | Что в ответе |
| --- | --- |
| Понял | задача одной фразой и что осталось непонятным |
| План | файлы, шаги, чем проверяется: тест, сид, прогон |
| Вопрос | только если данных нет; догадка вместо вопроса — ошибка |
| Код | после «делай», минимальным диффом |
| Отчёт | что изменено (пути), что запущено (команды и итог), что не проверено и почему |

«Одна фича — одно место» (`.docs/README.md`): описание живёт в своём файле, карточка на него ссылается,
а не пересказывает. Объём и порядок проверок — `.docs/testing.md`, ветки и готовность — `.docs/workflow.md`.
