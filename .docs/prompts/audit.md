# Аудит

```
Что аудитим: [файл, герой, фича или весь дифф перед merge]

По чему: .docs/rules/audit.mdc — чек-лист §1–§8; порядок шагов — .docs/skills/audit/SKILL.md
Что уже известно: [подозрения, прошлые поломки из .docs/pitfalls.md]

Что считаем риском: [нарушенный инвариант движка, скрытое поле в view, пустые данные, дубль правила,
мёртвый код, регрессия без теста]

Чем проверяем: [тесты затронутого файла; фаззинг по сидам — только под системную правку]
Формат отчёта: находки по критичности (блокер / важно), что проверено и чем, что не проверено и почему
```

- Аудит — не рефакторинг «заодно»: сначала список находок, правки пачками по темам и по отдельной команде.
- Прогоны под системную правку: `node node_modules\vitest\vitest.mjs run [файл] --pool=threads`,
  `node bot/tools/hotseat.js --games=500`. Вёрстку и стили не проверяем — их смотрит владелец.
- Сверять находку с кодом, а не с памятью: `.docs/rules/audit.mdc` местами отстаёт от текущего `shared/`.
