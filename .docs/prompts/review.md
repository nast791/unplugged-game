# Ревью диффа

```
Что ревьюим: [ветка / дифф / файлы: git diff и git diff --staged — часть правок уже в индексе]
Контекст задачи: [зачем правка, какая карточка или находка её породила]

На что смотреть: [слой — shared/, app/, server/, bot/, tests/, server/content/ — по .docs/review-rules.md]
Что считать дефектом: [блокеры: сломанное поведение движка, нарушенный инвариант, другой контракт
клиента, падение на пустых данных, расхождение с текстом карты]
Формат: файл:строка — что не так → что сделать; сначала блокеры, без похвалы и «мне кажется»
```

- Ревью — только текст: файлы не правятся, коммитов и стешей нет. Тредов, CI и автопрогонов в проекте нет.
- Вкусовое не пишем. Вёрстка, требования к тесту на неё и JSDoc — не дефекты (`.docs/review-rules.md`).
- Повторное ревью: исправленное не повторяется, неисправленное не дублируется — только новые находки.
- Блокеров больше десяти — так и написать: правка не готова.
