# Новая возможность

```
Зачем: [какую задачу игрока решаем — 1–2 предложения]

Что должно быть (поведение для игрока):
- [сценарий 1: что видно и что нажимается]
- [сценарий 2]

Критерий готовности: [что видно на экране / что лежит в view / какой тест зеленеет]

Где: [слой: движок shared/, сервер server/, клиент app/, контент server/content/, бот bot/]
Данные: [какие карты, герои, стихии: имена файлов или карт — «новая карта X героя Y»]
Что не трогать: [публичные имена, чужие герои, соседние экраны]

Макет (если интерфейс): [словами: где стоит, что нажимается, что меняется при клике; вёрстку
владелец проверяет глазами]
```

- Задача = новый герой, карта, компонент или движковый хук — назови скил из `.docs/skills/` и работай по
  нему: `new-hero`, `new-card`, `new-component`, `engine-change`.
- Нужен новый экшен или фаза — это отдельный шаг движка (`.docs/engine.md`), а не «заодно» внутри фичи.
- План до первой правки, код после «делай». Поведение важнее макета: макет словами, проверка глазами.
