# Рабочий процесс

Как в проекте делается правка: ветки и коммиты, объём проверок, готовность. Порядок четырёх шагов
(уточнили → план → «делай» → отчёт) живёт в `AGENTS.md` §2 — здесь то, что в него не помещается. Что и чем
проверяем — `.docs/testing.md`; что считать дефектом в диффе — `.docs/review-rules.md`.

## Git

| Что                   | Как                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------ |
| Рабочая ветка         | `develop` — работа идёт в ней                                                        |
| `master`              | вторая долгоживущая ветка; что и когда в неё сливается — решает владелец             |
| Ветка под задачу      | `git switch -c fix-<короткое-имя>`, когда правка того стоит (крупная или с разбором) |
| MR, стенды, пайплайны | нет: git обычный, GitHub как `origin`; стендов и CI в проекте нет                    |

- **Коммит и пуш — только по прямой команде владельца.** Агент не коммитит и не пушит по своей инициативе
  (`AGENTS.md` §2); «готово» означает «дифф готов», а не «залито».
- В дифф не попадает то, что скрыто в `.gitignore`: `.refs/`, `TODO`, `.workbuddy/` (скриншоты браузерного
  обхода), `.output/`, `.nuxt/`, `node_modules/`, `.env` и `*.env`, `logs`, `trainer/data/`.
- Перед коммитом — `git status` и `git diff`: в диффе только файлы задачи.

## Коммиты

Одна логическая правка — один коммит; сообщение по-русски, одной строкой, по существу:

```powershell
git add .docs/testing.md .docs/workflow.md
git commit -m "docs: описать уровни проверок и рабочий процесс"
```

- В истории проекта встречаются `fix` и `test: …` — префикс по типу правки (`fix:`, `docs:`, `test:`)
  читается в `git log` лучше, чем одно слово.
- «wip», «ещё немного» и «заодно» в историю не попадают: незаконченное не коммитится.

## Одна задача — один дифф

- Минимальный дифф: правим то, что просили. Чужие файлы не трогаем, «по дороге поправлю» — отдельная задача.
- Форматирование — только затронутые файлы, а не весь проект:

  ```powershell
  node node_modules\prettier\bin\prettier.cjs --write app\components\atoms\AButton.vue
  ```

  `pnpm format` (`prettier --write .`) переформатирует весь проект — для одной задачи это лишний шум.

- `.docs/` и `AGENTS.md` агент не правит по своей инициативе: документацию ведёт владелец, правка — по
  просьбе или когда этого требует сама правка кода (`.docs/README.md`, «Правила ведения»).
- Архитектурное предложение (новая зависимость, новый слой, рефакторинг структуры) обсуждается до кода.

## Что проверять при каком риске

Объём проверок определяется риском правки, а не важностью проекта. Команды — `.docs/testing.md`.

| Тип правки                               | Чем проверяем                                                                                       |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Цвета, отступы, шрифты, иконки, разметка | ничем: смотрит владелец глазами (`AGENTS.md` §6)                                                    |
| Тексты карт, подсказки, тултипы          | тест затронутого файла (`tests/unit/cards/`, `tests/unit/content/hints.test.js`)                    |
| Композабл клиента (`app/composables/`)   | unit-тест затронутого файла (`tests/unit/client/`)                                                  |
| Экран партии и панели                    | `tests/scenarios/hotseat-ui.test.js` с `$env:UI_SEEDS='10'`; канва — `hotseat-browser.mjs`          |
| Движок (`shared/`)                       | его unit-тесты + `tests/unit/core/immutability.test.js` + `node bot/tools/run.js --seeds=200`       |
| Генератор, стихии, старты                | `tests/unit/content/generator.test.js` + `tests/scenarios/hotseat.test.js`                          |
| Контент героя или колоды                 | `tests/unit/cards/`, `tests/unit/content/`, `tests/unit/skills/` + `pnpm test:matrix -- --games=20` |
| Бот (`bot/`)                             | `tests/unit/bot/` + `bot/tools/stall.js`, `waste.js`, `matrix.js`                                   |
| `nuxt.config.ts`, зависимости            | полный набор + сборка `node node_modules\nuxt\bin\nuxt.mjs build`                                   |
| `.docs/`, `AGENTS.md`                    | ничем: проверяем, что команды и пути в тексте живые                                                 |

Полный прогон (весь набор + фаззинг + сборка) — при системной правке или по прямой просьбе владельца;
«правка косметическая, проверок не требует» — нормальный ответ, молчание — нет.

## Готовность (DoD)

Задача закрыта, когда:

1. правка делает ровно задачу, а дифф минимальный;
2. пройден минимум проверок из таблицы выше, а в отчёте сказано, что запущено, а что нет и почему;
3. найденная поломка закрыта тестом, и этот тест остаётся (`.docs/testing.md`, «Известный долг»);
4. нет отладочного мусора: `console.log`, закомментированных блоков, мёртвых экспортов;
5. документация не разошлась с кодом: изменилось поведение — текст правит владелец или это часть задачи;
6. в дифф не попали файлы из `.gitignore` и чужие правки;
7. коммит и пуш сделаны только по команде владельца — или не сделаны, и это сказано вслух.

Полный аудит перед крупной сдачей — `.docs/rules/audit.mdc`.

## Как работать с ИИ-агентом

Порядок из четырёх шагов — `AGENTS.md` §2. Здесь то, чего в нём нет.

**План до кода.** Агент перечисляет: что меняет, какие файлы затронет, чем проверяет — 3–7 пунктов, без
сочинения на полстраницы. План — договор: правка в его рамках норма, расширение «заодно» — новый запрос.

**«Делай» — это разрешение.** До него кода нет. В запросе — задача, контекст и границы: какой раздел
`.docs` смотреть, какие файлы можно трогать, что считать готовым. Один запрос — одна задача; длинная сессия
с десятком тем путает агента и переплачивает за контекст.

**Отчёт после работы** — три пункта, всегда:

1. **что изменено** — путями (`shared/phases/defense.js`, `.docs/testing.md`);
2. **что запущено** — командами и результатом (`node node_modules\vitest\vitest.mjs run …` — 4 passed);
3. **что не проверено и почему** («вёрстка — смотрит владелец», «сборку не гонял: правка не системная»).

Третий пункт важнее первых двух: пропущенный, он читается как «проверено всё».

**Типовые сбои и что делать**

| Симптом                              | Причина                                                           | Действие                                                                                 |
| ------------------------------------ | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| появился `.ts`-файл или `lang="ts"`  | привычка модели                                                   | откатить: язык проекта — JS и `<script setup>` без `lang` (`.docs/rules/code-style.mdc`) |
| `<style scoped>` в компоненте        | привычка из другого проекта                                       | убрать: классы Tailwind прямо в разметке (`.docs/rules/code-style.mdc`)                  |
| `Failed to resolve component`        | автоимпорта компонентов нет (`components: []` в `nuxt.config.ts`) | явный `import AButton from '~/components/atoms/AButton.vue'`                             |
| прогнал полный набор после косметики | «на всякий случай»                                                | не гонять: `.docs/testing.md`, «Объём»                                                   |
| поправил отступы соседнего файла     | широкий дифф                                                      | вернуть лишнее, дифф — только по задаче                                                  |
| `pnpm exec …` падает                 | PowerShell 5.1 и песочница                                        | запускать бинарь напрямую: `node node_modules\…`                                         |
| закоммитил сам                       | «казалось, так надо»                                              | коммит и пуш — только по команде владельца                                               |

Агент — исполнитель, а не автор решений: задачу, критерии и границы задаёт человек.

## Обновление стека и зависимостей

- Версии в `package.json` зафиксированы без `^` (`README.md`): обновление — осознанная правка версии, а не
  `pnpm update` по всему дереву.
- Порядок: правка `package.json` → `pnpm install` (обновляет `pnpm-lock.yaml`) → `pnpm run postinstall`, если
  `.nuxt` пуст → проверки по таблице выше → сборка.
- Мажор Nuxt, Vue, konva или vitest — отдельная задача: CHANGELOG прочитан, полный набор и сборка прогнаны.
  В одном диффе с фичей обновление не едет.
- Новая зависимость заводится, когда без неё нельзя, и с объяснением зачем. `playwright-core`, `sharp` и
  `fast-glob` уже стоят ради браузерного обхода и пекарей, а не ради рантайма игры.
- `pnpm clean` (`nuxt cleanup`) — когда `.nuxt` или кэш мешают, а не «на всякий случай».

## Аварийные сценарии

Установка, порт, кодировка и сборка разобраны в `.docs/onboarding.md` §1 и §4 — здесь решения, а не повтор.

| Ситуация                 | Что делать                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| упал `pnpm install`      | версия Node (`engines: >= 20`, `engine=strict` в `.npmrc`) → `pnpm clean` → повторить; `pnpm-lock.yaml` руками не правим |
| сломался `pnpm dev`      | читать `ERR_…` в выводе: занят порт 3000 — `pnpm dev -- --port=3001`; пустой `.nuxt` — `pnpm run postinstall`            |
| партия «потерялась»      | партии живут в памяти процесса (`server/party.js`), рестарт dev их не переживает — собрать новую; это не потеря данных   |
| правка ушла не туда      | `git status`, затем `git restore <файл>`: откат одного файла; чужие правки не откатываем — говорим о них                 |
| проверка упала непонятно | `.docs/testing.md`, «Если прогон упал»: сначала один файл и сид из сообщения                                             |
| кириллица стала мусором  | файл перезаписан ANSI-инструментом: править только инструментами записи (UTF-8), читать `Get-Content -Encoding UTF8`     |
