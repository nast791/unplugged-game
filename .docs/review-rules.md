# Правила ревью диффа

Один источник для человека и ИИ-агента: что считать дефектом, а что нет. Ревью идёт по диффу —
только изменённые файлы и строки, остальной код нужен как контекст. GitLab, робота-ревьюера и CI в
проекте нет, тредов тоже нет: замечания отдаются списком.

Стиль кода — `.docs/rules/code-style.mdc`, поведение движка — `.docs/engine.md`, интерфейс —
`.docs/ui.md` и `.docs/cards-ui.md`. На правило ссылаемся путём, а не пересказом. Порядок шагов ревью —
`.docs/skills/code-review/SKILL.md`, ветки и готовность правки — `.docs/workflow.md`.

## Источник и границы (Git)

| Что          | Как                                                                     |
| ------------ | ----------------------------------------------------------------------- |
| Дифф целиком | `git diff` **и** `git diff --staged` — часть правок уже в индексе       |
| Один файл    | `git diff -- <путь>`, `git diff --staged -- <путь>`                     |
| Границы      | только изменённые файлы и строки; чистый файл рядом — не материал ревью |

- Во время ревью **ничего не коммитим, не пушим, не стешим, не ребейзим и не правим файлы**: находка —
  это текст с путём и строкой, правку делает автор.
- Тредов нет: резолвить нечего. Повторное ревью начинается с прошлых замечаний — исправленное не
  повторяется, неисправленное не дублируется, только после этого пишутся новые находки.
- `.refs/`, `TODO`, `.workbuddy/`, `trainer/data/` в диффе не участвуют (`.gitignore`); файл оттуда в
  диффе — ошибка правки `.gitignore`, а не материал ревью.
- Прогонов в ревью нет: тесты гоняет автор, порядок — `.docs/testing.md`. Ревью не требует «докажи
  прогоном» и не считает зелёный прогон аргументом за отсутствие дефекта.

## Блокеры

| Находка                     | Признак                                                                                                                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сломано поведение движка    | окно не открывается или не закрывается, шаг «сработал» без изменений, обязательное окно встаёт намертво                                                                                                    |
| Расхождение с текстом карты | `server/content/**/cards.js` обещает одно, правило делает другое — игрок читает карту, а не код                                                                                                            |
| Нарушен инвариант           | ссылка на `.docs/engine.md`: мутация входного состояния в `runAction`, `Math.random`/`Date.now` в логике, неизвестный момент, `auto` и `manual` вместе, `frozen` без проверки там, где карта двигает бойца |
| Сломан контракт клиента     | клиент шлёт не `PICK`/`UI_*`, действие правит чужое состояние, проекция отдаёт чужим скрытое                                                                                                               |
| Падение на пустых данных    | `node.terrain` без стихии, пустой список бойцов, неизвестная стихия в `terrainColor`/`terrainPattern`                                                                                                      |
| Сломанная карта             | номерная клетка не одноцветная, старты ближе `START_GAP_STEPS`, поле с разрывом области, линия не влезает в предел связей                                                                                  |

## Важно

- **Производительность:** `structuredClone` вместо форка (`shared/helpers/fork.js`), BFS или генератор
  в цикле рендера, пересчёт проекции на каждый клик, лишний проход по всем клеткам в правиле.
- **Дубли правил:** меняемые числа мимо `shared/constants/tuning.js`, тексты подсказок мимо
  `shared/constants/hints.js`, метки карты мимо `CARD_TAGS`, стихии мимо палитры `terrain.js`.
- **Мёртвый код:** неиспользуемые экспорты, параметры «на будущее», ветка, которую не может включить ни
  одно правило контента.
- **Регрессия без теста:** инвариант движка уже стережётся существующим тестом, а правка его не
  обновила. Тест на вёрстку при этом не требуется (ниже).

## Не является дефектом

| Что                                                   | Почему                                                                                                                                         |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Стиль, зафиксированный в `.docs/rules/code-style.mdc` | стрелочные функции, fluid-утилиты, `<section>` в организме, отсутствие `<style>`, комментарии только в `.js` — это норма проекта, а не находка |
| Нет теста на вёрстку                                  | вёрстку не тестируем: правки дизайна смотрит владелец глазами (`.docs/testing.md`)                                                             |
| «Нет JSDoc»                                           | JSDoc в проекте **запрещён** (`.docs/rules/code-style.mdc`, «Документация в коде»)                                                             |
| Переносы, кавычки, тире, регистр                      | вкусовщина; текст сверяется с картой и дизайном, а не с правилами языка                                                                        |
| Документация и паспорта героев                        | `.docs/**` и `server/content/heroes/*/passport.md` читаются смыслом, построчных замечаний по ним нет                                           |
| Моковые данные, заглушки, `TODO`                      | незавершённое очевидно ждёт реализации                                                                                                         |
| Разные имена у одного и того же в двух словарях       | не дефект, пока словарь один на всех и ключи не собираются конкатенацией                                                                       |

## Что не читается построчно

Список — `.docs/review-ignore.txt`. Правило одной строки: **есть в диффе хоть один файл вне списка —
ревью полное**; дифф только из файлов списка — построчное ревью не нужно, остаётся смысл.
Пропущенное в итог не пишется — иначе читатель ищет замечание, которого нет.

## Формат комментария

```
файл:строка — что не так → что сделать
shared/actions/movement.js:42 — телепорт ставит movedThisTurn → передать teleport: true
```

- Метки: `[блокер]`, `[важно]`; находки идут по критичности, сначала блокеры. Вкусовое не пишется ни
  под какой меткой.
- Один комментарий — один дефект. Системная находка — один раз, остальные строки списком в тексте.
- Без «мне кажется», «возможно», «я бы»: только факт, причина и действие. Без похвалы и без «что
  сделано хорошо».
- Ссылка на правило путём и названием инварианта (`.docs/engine.md`, «Телепорт — не движение»), а не
  пересказ правила своими словами.
- Замечание сверяется с текущей строкой диффа: если предлагаемая правка уже написана — находки нет.
- Блокеров больше десяти — так и написать в итоге: правка не готова.
