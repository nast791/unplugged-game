# 0007. Ход считается на форке, а не на `structuredClone`

- **Дата:** 2026-11-17
- **Статус:** принято

## Контекст

Кирпичи правят вложенные объекты на месте: `SET_HEALTH` убирает бойца из `player.fighters`, `SET_ITEM` меняет
`item.state`. Чтобы откатить пробный ход, нужна копия «до», но копировать состояние на каждый ход дорого.

## Решение

Движок форкает сам: `forkState` (`shared/helpers/fork.js`) копирует только изменяемые ветки — `forkList`,
`forkMap`, `forkZone`, `forkPlayer`, `forkCombat`, `forkMovement`. `structuredClone` не используется: он в
7,5 раза дороже, а форк стоит ноль (200 партий — 2762 мс против 2771 мс без форка).

## Следствия

- Новая ветка состояния обязана попасть в `forkState`, иначе её правки утекут в исходное состояние.
- `null` и `[]` различимы: `movement.fighters: null` — двигаются все, `[]` — никто.
- `tests/unit/core/immutability.test.js` форкает состояния из `IMMUTABLE_SEEDS` и пробует действия из
  `IMMUTABLE_STEPS` через `firstDiff` — правка «на месте» ловится здесь.
- Устройство движка — `.docs/engine.md`, поток по файлам — `.docs/rules/internal-logic.mdc`.

## Альтернативы

- **`structuredClone` на каждое действие.** Отклонено: 7,5× медленнее, бот и тесты встают.
- **Иммутабельные кирпичи.** Отклонено: переписывать движок и контент героев ради чистоты.
