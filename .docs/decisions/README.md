# Решения (ADR)

Короткие записи «почему так»: одна страница на решение. Нужны, чтобы через полгода не спорить заново и
чтобы агент не предлагал отменённый подход как новый.

## Формат

Файл `NNNN-kebab-name.md`, около 25 строк:

```md
# NNNN. Короткое решение

- **Дата:** ГГГГ-ММ-ДД
- **Статус:** принято | заменено NNNN

## Контекст

2–4 строки: какая была проблема или выбор.

## Решение

1–3 строки: что решили, с именами файлов и функций.

## Следствия

2–4 пункта: что из этого следует для кода и проверок (пути, тесты).

## Альтернативы

1–3 пункта: что рассматривали и почему отвергли.
```

## Правила

- Решение не переписывается. Изменилось — новый ADR, у старого статус «заменено NNNN».
- Здесь только «почему». Как писать код — `.docs/rules/code-style.mdc`, как устроено — `.docs/engine.md`,
  `.docs/terrain.md`, `.docs/ui.md`.
- ADR не дублирует предметные доки: ссылки на них в «Следствиях» достаточно.
- Ведёт владелец проекта; агент добавляет ADR по прямой просьбе.
