# Первый день в проекте

Короткий путь от «клонировал репозиторий» до первого диффа. Правила, тесты и порядок работ здесь
**не пересказываются** — на них даны ссылки; этот файл только про вход.

## 1. Установка и запуск

```powershell
node -v          # engines: >= 20 (на проекте Node 24)
corepack enable  # pnpm 11.10.0 из packageManager
pnpm install     # postinstall = nuxt prepare
pnpm dev         # http://localhost:3000, партия — /game
```

| Что                 | Значение                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| Node                | `engines: >= 20` в `package.json`, `engine=strict` в `.npmrc` — версия не из диапазона роняет `pnpm install` |
| pnpm                | `packageManager: pnpm@11.10.0`                                                                               |
| Порт `pnpm dev`     | 3000: в `nuxt.config.ts` порт не переопределён, Nuxt берёт свой по умолчанию                                 |
| Другой порт         | `pnpm dev -- --port=3001`                                                                                    |
| Клиентские маршруты | `/game` и `/heroes/**` — `ssr: false` (`routeRules`), `/` рендерится на сервере                              |

### Если `postinstall` не отработал

Признаки: нет папки `.nuxt/`, а `tsconfig.json` ссылается на `.nuxt/tsconfig.app.json` и соседние; не
разрешаются алиасы `~`, `@`, `#shared`; падают импорты компонентов.

```powershell
pnpm run postinstall                          # то же, что nuxt prepare
node node_modules\nuxt\bin\nuxt.mjs prepare   # если скрипты pnpm в песочнице не идут
pnpm clean                                    # = nuxt cleanup, затем повторить install
```

## 3. Первый дифф

- **Одна задача — один дифф.** Чужие файлы не трогаем, «заодно поправлю» — отдельная задача.
- Форматирование — только затронутые файлы, не весь проект:

```powershell
node node_modules\prettier\bin\prettier.cjs --write app\components\atoms\AButton.vue
```

- Тесты — целевой файл, а не весь набор:

```powershell
node node_modules\vitest\vitest.mjs run tests/unit/client/card-text.test.js --pool=threads
```

- Что и когда гонять (полный набор, сборка, фаззинг) — `.docs/testing.md`.
- Ветки, коммиты, пуш — `.docs/workflow.md`. **Коммит и пуш — только по прямой команде владельца.**

## 4. Если что-то не работает

| Симптом                                | Что делать                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev` не поднялся                 | сначала версия Node (`engine=strict`), потом занятый порт: `EADDRINUSE` — другой порт `pnpm dev -- --port=3001`; остальное — читать строку `ERR_…` в выводе, она называет причину                                                                                                                                            |
| кириллица в файле превратилась в мусор | PowerShell 5.1 читает и пишет UTF-8 как ANSI: файл на экране выглядит как `РљСЌС€` (ровно так выглядят `.prettierignore` и комментарий в `vitest.config.ts`). Сами файлы целы, пока их не перезаписали: **править только инструментами записи или Node с `fs` в UTF-8**; для чтения в консоли — `Get-Content -Encoding UTF8` |
| партия пропала после перезагрузки      | партии живут **в памяти процесса** `server/party.js` (`const parties = new Map()`), сохраняются снимком состояния (`save`) и удаляются по лимиту `LIMITS.parties`; рестарт `nuxt dev` их не переживает — это не баг сохранности                                                                                              |
| упал `nuxt build`                      | сборка идёт 5–6 минут, поэтому гоняем её только под системную правку (движок, генератор, контент-схемы, конфиг сборки, зависимости): `node node_modules\nuxt\bin\nuxt.mjs build`                                                                                                                                             |
| `pnpm exec` не работает в sandbox      | запускать бинарь напрямую: `node node_modules\vitest\vitest.mjs`, `node node_modules\prettier\bin\prettier.cjs`, `node node_modules\nuxt\bin\nuxt.mjs` — тот же эффект, без оболочки pnpm                                                                                                                                    |

## 5. `.refs/`

Каталог скрыт от git (`.gitignore`) — это выгрузки и чужие материалы: **читаем глазами и только**.
Из него ничего не попадает в `server/content/`: контент пишем свой, по правилам пака.
