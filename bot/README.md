# Бот

Здесь всё про бота: игра за сторону, прогоны серий, метрики и матрица матчапов. Тесты бота лежат в
`tests/` (vitest берёт только `tests/**/*.test.js`), поэтому логика — тут, проверки — там
(`tests/unit/bot/`, `tests/scenarios/*-fuzz.test.js`).

**Играет — `bot/play/`** (эта папка уезжает в браузерный бандл: ни `node:`, ни серверного реестра)

| Файл | Что там |
| --- | --- |
| `bot/play/pool.js` | пул героев из `server/content`: пары, колоды, типы карт; Медуза и Тесла — эталон оригинала |
| `bot/play/policy.js` | политики бота: `random` (веса фаззинга), `greedy` (осмысленная игра: рука, цена карты, выбор цели, ценность карты в бою, свойства героя, позиция и усталость), `trade` (**живая в браузере**: тот же жадный плюс темп по запасу колод — позади давить, впереди тянуть, §36), `pressure` (кандидат: давит и идёт в контакт, §36), `conditions` (тот же жадный, но карта оценивается по **своим правилам** — «Погребальный звон» это 6, пока Анубис не двигался), `search`/`net`/`matchup`/`plain`/`turn` (поиск с ручным листом, обученной моделью, весами пары, прежней формулой и листом на границе хода — §25), `qprior` (поиск, которому варианты подсказывает обученная модель, §24), `chain` (планировщик цепочек до конца хода, §25), `qvalue` (веса разрешённых вариантов переставляет обученная модель пары «состояние + действие», §22), `cards` (без признаков позиции и усталости — эталон §13–§14), `economy` (без признаков карты и свойства — эталон §12), `basic` (вообще без признаков — эталон §10); политика — веса, а не код |
| `bot/play/cards.js` | оценка **своих** карт и умений: что вариант свойства даёт и чем платит (`optionWorth`), сила карты, метки ресурса, **обещание карты** (`cardPromise`: условия правила проверяет движок — покой, стихия, чужая рука, состояние предмета) |
| `bot/play/counting.js` | подсчёт карт: остаток колоды соперника (`unseenOf`, `remainingOf`), ожидание числа атаки по остатку (`expectedAttack`), сколько копий карты ещё может быть (`remainingCount`) |
| `bot/play/search.js` | поиск по детерминизациям (SO-ISMCTS): фабрика «возможных миров» (`worldFactory`, ленивая сборка), оценка позиции (`leafScore`), дерево с UCT (`searchAction`), доигрывание (`rolloutEnd`: предел глубины, конец хода или ответ соперника — §25), приор корня (`rootPriors`: вес политики или оценка ученика — §24), бюджет (`searchBudget`), границы хода (`myTurnOf`, `turnOver`) |
| `bot/play/plan.js` | планировщик хода: цепочки своих действий до конца хода, оценка каждой доигрыванием до конца хода и ответа соперника на общих мирах (`turnPlan`, `planBudget`) — политика `chain`, §25. Проиграл поиску (48%) и остался инструментом, а не рабочей политикой |
| `bot/play/value.js`, `bot/play/value-weights.js` | оценка листа линейной моделью на признаках (63: 15 базовых, 12 индикаторов, 36 взаимодействий с героем). Блок героя — §18; ресурс из пака — §19; покой, чужая рука, помощники и заморозка — §20; взаимодействия дают **вес признака на пару**, из них считается матрица матчапов. Веса обучены `bot/learn/train.js` и перезаписываются им |
| `bot/play/matchups.js`, `bot/play/matchups.json`, `bot/play/matchup-weights.js` | матрица матчапов — **точная проекция** модели на пару «мой герой против этого соперника»: JSON для чтения, JS-зеркало для бандла (в браузере нет `fs`). Оба файла пишет `bot/learn/train.js`; `pairScore` даёт то же число, что полный вектор, это стережёт `tests/unit/bot/matchups.test.js` |
| `bot/play/resources.js` | ресурс героя **из пака**: порог механики берётся из правил умения (`ITEMS { group, state }`, `CARDS { zone: 'discard', tag }`), готовность — из источника, который эти правила читают (копии предмета или сброс), топливо — карты, которые ресурс двигают (§19) |
| `bot/play/axes.js` | оси героя из пака: читает ли пак своего героя через `movedThisTurn` (`stillnessMatters`, вес покоя для листа поиска) — §21 |
| `bot/play/actionFeatures.js` | признаки варианта хода (20 чисел: вид действия, сила и тип карты, обещание по её правилам, цель, клетка, вес политики) — общие для обучения и игры, поэтому учились и играют на одном |
| `bot/play/qvalue.js`, `bot/play/qvalue-weights.js` | оценка пары «состояние + действие» из артефакта тренера (`trainer/`): переставляет веса разрешённых вариантов (вес 0 — вето политики) — политика `qvalue`, а её же числа служат приором корня поиска — политика `qprior` (§22–§24). Читает **оба** вида артефакта: линейный (`linear-q`) и сеть (`mlp-q`, forward-pass с эмбеддингами героев и карт, §28) |
| `bot/play/ai.js` | ход компьютера: `think(state, playerId, { timeMs })`, слоты `ai` (`aiSeatIds`, `isAiSeat`) и шаг цикла `aiStep` — **без серверных зависимостей**, этот же код зовёт клиент в `vs_ai`. Перечисляет политикой `conditions` (условия своих карт), лист — ручная формула §21 (ресурс, помощники, покой) |
| `bot/play/decide.js` | ядро решений: `actorOf`, `actionsFor`, перечисление действий и кэш карт расстояний; тоже без серверных зависимостей (в браузере работает именно оно) |
| `bot/play/duel.js` | бот-игрок: сборка партии (`createDuel`, в том числе `vsAi`) и прогон (`playDuel`); перечисление действий берёт из `decide.js` |
| `bot/play/metrics.js` | метрики партии: урон, покрытие колоды, распределение действий, потраченные в ходу действия (`turns`/`fullTurns` — §25), первое убийство |

**Учит — `bot/learn/`** (офлайн)

| Файл | Что там |
| --- | --- |
| `bot/learn/train.js` | обучение оценки на трассах поиска: самоигра в воркерах (`--workers=N`), подписи по исходу партии, логистическая регрессия |
| `bot/learn/samples.js` | сбор выборки для обучения: снимок признаков на каждом `--sample-every`-м шаге и подпись «выиграл / проиграл» |
| `bot/learn/parallel.js` | параллельные прогоны: партии делятся между воркерами (`runGamesParallel`), выборка для обучения (`runSampleGames`), матрица в воркерах (`runMatrixParallel`) |
| `bot/learn/worker.js` | воркер: играет одну партию и отсылает отчёт (в режиме `collect` — выборку признаков) |
| `bot/learn/export.js` | поставщик партий для Python-тренера: играет движком и стримит JSONL-контракт «состояние + варианты хода + что выбрал поиск + исход + **ценность хода** (`turn` — оценка позиции сразу после своего хода, §26)» (`trainer/README.md`) — правила остаются в JS, тренер их не повторяет (§22) |

**Меряет — `bot/tools/`**

| Файл | Что там |
| --- | --- |
| `bot/tools/think.js` | CLI-проба хода с бюджетом времени: `node bot/tools/think.js --time=1000` |
| `bot/tools/tuner.js` | подбор весов политики: покоординатный спуск по винрейту против эталона, проверка на удержанных сидах |
| `bot/tools/sweep.js` | серия прогонов и отчёт: `runSweep`, `describeSweep`, `failuresOf` |
| `bot/tools/matchup.js` | матрица матчапов как данные: `runMatrix`, таблицы, коридоры, «лестница» в обе стороны (`firstSeatWins`, `ladderAggregateLine`) |
| `bot/tools/run.js` | ручной прогон пары (`pnpm test:bot`) |
| `bot/tools/matrix.js` | матрица «все против всех» с метриками по героям (`pnpm test:matrix`) |
| `bot/tools/stats.js` | замер политики против политики **с разрезом по героям**: те же партии играются обеими сторонами, сравниваются винрейты держателя политики и держателя эталона (§33) |
| `bot/tools/rank.js` | аудит цели: доля пар, где модель согласна с целью дневника (веса, визиты, ценность варианта, сыгранное действие) — видно, где конвейер работает, а где цель не берётся (§27) |
| `bot/tools/waste.js` | замер «карты не впустую»: сколько эффектных карт сыграно и у скольких свойство не сработало (`effectWorth.fires`), плюс длина партии и доля истощений (§35) |
| `bot/tools/stall.js` | замер «партия не тянется»: медиана длины, конец убийством против истощения, винрейты политик в обе стороны (`--policy=pressure --policy-b=greedy`) (§36) |

```powershell
pnpm test:bot                                          # эталонная пара, 60 партий, случайный бот
node bot/tools/run.js --seeds=200 --heroes=anubis,dorothy    # любая пара из контента
node bot/tools/run.js --seeds=200 --policy=greedy            # осмысленная политика
pnpm test:matrix -- --games=200                        # все пары: матрица + сводка (по умолчанию greedy)
pnpm test:matrix -- --games=20 --heroes=anubis,tesla   # одна пара
pnpm test:matrix -- --policy=greedy --policy-b=random   # «лестница»: жадный против случайного, в обе стороны
pnpm test:matrix -- --policy=greedy --policy-b=basic    # вклад всех признаков: с признаками против без них
pnpm test:matrix -- --policy=greedy --policy-b=economy  # вклад этапа §13: карты в бою и свойства героя
pnpm test:matrix -- --policy=greedy --policy-b=cards   # вклад позиции и усталости (§15)
pnpm test:matrix -- --policy=search --policy-b=greedy --games=10   # поиск против жадной политики (§16)
pnpm test:matrix -- --policy=search --policy-b=greedy --games=10 --workers=8   # то же, партии в 8 воркеров
pnpm test:matrix -- --policy=net --policy-b=search --games=10 --workers=8      # две оценки листа друг против друга
pnpm test:matrix -- --policy=conditions --policy-b=greedy --games=60 --workers=8  # вклад условий карт (§20)
pnpm test:matrix -- --policy=matchup --policy-b=search --games=10 --workers=8   # лист весами пары (§20)
pnpm test:matrix -- --policy=search --policy-b=plain --games=10 --workers=8    # вклад ресурса, помощников и покоя в лист (§21)
pnpm test:matrix -- --policy=qvalue --policy-b=greedy --games=10 --workers=8   # обученная оценка пары «состояние + действие» (§22)
node bot/tools/stats.js --games=200 --workers=12 --policy=qvalue --policy-b=greedy   # то же с разрезом по героям (§33)
node bot/tools/stats.js --games=20 --workers=8 --max-steps=200 --policy=qthink --policy-b=greedy --depth=0,1,2  # думанье по глубинам (§32–§33)
node bot/tools/waste.js --games=60 --policy=greedy               # карты не впустую: доля эффектов без срабатывания (§35)
node bot/tools/stall.js --games=40 --workers=8 --policy=pressure --policy-b=greedy   # длина партии и истощение, обе стороны (§36)
pnpm test:matrix -- --policy=qprior --policy-b=search --games=10 --workers=12  # вклад приора от ученика в поиск (§24)
pnpm test:matrix -- --policy=turn --policy-b=search --games=10 --workers=12   # лист на границе хода (§25)
pnpm test:matrix -- --policy=chain --policy-b=search --games=10 --workers=12  # планировщик цепочек (§25, дорого)
node bot/tools/rank.js --data=trainer/data/greedy.jsonl.gz --target=prior    # аудит: различает ли модель варианты (§27)
node bot/tools/think.js --time=1000 --samples=5              # проба хода с бюджетом времени (тот же код, что в браузере)
node bot/learn/train.js --games=300 --epochs=400 --workers=8 # обучить оценку на трассах поиска (партии в воркерах)
node bot/learn/export.js --games=3000 --policy=greedy --out=trainer/data/greedy.jsonl.gz --gzip  # данные для Python-тренера (§22)
node bot/learn/export.js --games=300 --policy=qvalue --out=trainer/data/self.jsonl.gz --gzip   # дневник ученика: партии играет сам qvalue (§23)
node bot/learn/export.js --games=3000 --policy=search --out=trainer/data/search.jsonl.gz --gzip  # дневник учителя-поиска: цель политики — доли доигрываний (§24)
node bot/tools/tuner.js --minutes=6                          # подбор весов политики против эталона
```

Обучение оценки «пары состояние + действие» живёт отдельно — `trainer/` на Python (контракт, запуск и
формат артефакта — `trainer/README.md`): движок играет партии и стримит JSONL, Python учит модель, игра
читает артефакт (`bot/play/qvalue.js`, политика `qvalue`).

Поиск дороже весов: один ход — десятки доигрываний партии, поэтому в прогонах его берут с `--games=10`,
а партии считают воркерами (`--workers=N`; по умолчанию один процесс). Бюджет настраивается переменными
среды: `SEARCH_ITERATIONS` (32, а при заданном `SEARCH_TIME` — снимается сам), `SEARCH_DEPTH` (10),
`SEARCH_TREE_DEPTH` (3; 1 — плоский поиск без дерева), `SEARCH_TIME` (мс — предел **на решение**: он
режется и между доигрываниями, и внутри каждого из них, `searchAction` отдаёт `elapsed` и `timedOut`),
`SEARCH_ROLLOUT` (`aggressive`), `SEARCH_PRIOR` (коэффициент приора), `SEARCH_PRIOR_FROM` (`weights` |
`qvalue` — откуда берётся приор корня, §24), `SEARCH_TURN_END` / `SEARCH_TURN_REPLY` (`1` — лист на границе
хода; их включает политика `turn`, а вне своего хода поиск снимает их сам — в чужом бою границы хода нет),
`SEARCH_GAMMA`, `SEARCH_EVAL` (`heuristic` | `position` — та же формула плюс геометрия: угроза герою,
давление на чужого героя, прикрытие своими бойцами | `net`), `QVALUE_TEMPERATURE` (температура выбора
обученной политики; 0 — чистый argmax модели), `QVALUE_PRIOR_MIX` (примесь мнения политики к оценке
ученика, по умолчанию 0.3; 0 — чистая модель, §29), `PLAN_STEPS` / `PLAN_WORLDS` / `PLAN_DEPTH` /
`PLAN_BRANCH` / `PLAN_HORIZON` / `PLAN_TIME` (бюджет планировщика хода, §25; `PLAN_REPLY=0` — без ответа
соперника). Длина партии ограничивается `--max-steps=N`.

Лестница меряется **в обе стороны** (политика играет и первым, и вторым местом) — это вдвое дольше, но
иначе не отделить силу политики от перевеса первого места: первый игрок сам по себе выигрывает 54–61%.

Что бот ищет и чего не делает:

- находки — `crash`, `deadlock`, `noop`, `invalid`, `stuck`; отчёт печатает сид, шаг и последние
  действия, по ним партия повторяется один в один;
- **политики:** `random` ходит почти наугад и нужен для покрытия (он лезет в редкие ветки карт),
  `greedy` играет осмысленно — защищается картой, выходит на дистанцию удара, отходит из-под удара, когда
  по нему не достают оттуда, откуда он сам бьёт, встаёт на свою стихию, следит за рукой (при 0–1 карте
  сначала добирает), бережёт сильные карты, добивает раненых именно той картой, которой хватает,
  оценивает варианты свойств по своей карте и не крутит колоду на исходе. `search` — не веса, а поиск по
  детерминизациям (`bot/play/search.js`): мир собирается из остатка чужой колоды, дерево растёт по UCT, лист
  оценивается по здоровью и запасу колоды. `aggressive` — та же жадная политика с усиленной атакой: она
  доигрывает партии внутри поиска, чтобы оценка видела бой, а не стояние. `conditions` — жадный, который
  читает условия **своих** карт («Погребальный звон» это 6, пока Анубис не двигался); `net` и `matchup` —
  поиск с обученной оценкой листа (полным вектором и весами пары). `cards` — без признаков позиции
  и усталости (§13–§14), `economy` — без признаков карты и свойства (§12), `basic` — вообще без признаков
  (§10); разница между ними и `greedy` и есть вклад признаков. Метрики читают по `greedy`: числа `random` —
  это свойство случайного бота, а не сила героев;
- чужой руки не читает: решения строятся на `runUi` (своя рука, бойцы на поле) и содержимом **своих**
  карт, поэтому метрики честные. Скрытое число атаки (`combat.attackValue`) бот тоже не читает: до
  вскрытия проекция отдаёт его только владельцу карты, поэтому защитник решает по ожиданию из остатка
  колоды соперника (`bot/play/counting.js`) — как живой игрок, который помнит, что уже вышло;
- зеркал нет: `player.id` — это id героя, а валидация запрещает взять одного героя дважды.
